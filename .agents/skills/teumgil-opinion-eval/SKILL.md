# 의견 초안 AI 변경·평가

프롬프트·스키마·검증기·사례의 의미를 함께 유지한다. 기준 출력 검사와 실제 모델 평가의 증거를 구별한다.

## 기준과 도구

- 사용 방식·입력·출력 의미: [앱 AI 안내](../../../docs/prompts/README.md).
- 고정 지침: [시스템 프롬프트](../../../docs/prompts/opinion-draft.system.md).
- 구조: [JSON Schema](../../../docs/prompts/opinion-draft.schema.json).
- 사례와 사실성 검토: [가상 사례](../../../evals/opinions/cases.json).
- 실행·보고서·출처 구분: [하네스](../../../docs/HARNESS.md).

위 경로는 이 스킬 디렉터리 기준이다. 명령은 저장소 루트에서 실행한다. 구체 규칙은 원본을 읽으며 이 파일에 복사하지 않는다.

## 변경할 때

1. 요청이 지침·출력 구조·검증·평가 중 무엇을 바꾸는지 확인하고, 해당 파일과 실제 [검증기](../../../scripts/lib/opinions.mjs)·테스트를 읽는다.
2. 의미 변경 전 `npm run eval:fingerprints`로 현재 버전을 확인한다. 관련 회귀 사례를 확인하고, 문제를 재현하는 가상 입력과 기대 동작이 없으면 추가한다. 실제 개인정보를 사례에 넣지 않는다.
3. 고정 지침·스키마·업무 검증·안내 예시·기준 출력을 영향받는 범위에서 함께 맞춘다. 검증 기준을 낮추거나 실패 사례를 제거해 통과시키지 않는다.
4. 원문의 사실·모르는 정보·상충 진술·명령 삽입·개인정보를 관련 사례로 확인한다. 생성 상태와 앱의 접수·처리 상태를 연결하지 않는다.
5. 관련 검사를 하고 `npm run verify`와 변경 후 fingerprints를 확인한다. 기준 출력 통과는 도구와 사람이 쓴 사례의 일관성만 입증한다.

## 수집한 출력을 평가할 때

- 파일이 있으면 `npm run eval:outputs -- <출력파일>`을 실행한다. 자료의 생성 방식을 `model/template/manual` 중 실제 값으로 기록해야 한다.
- 누락·중복 사례, 버전 불일치, 잘못된 JSON이면 거부 결과를 보고한다. 파일을 임의 완성하거나 fixture를 모델 결과로 바꾸지 않는다.
- JSON·조건 통과와 원문 사실성·중립성·개인정보의 사람 검토를 구분한다. 메타데이터의 모델명은 선언이지 API 호출 증명이 아니다.
- 실제 출력이나 허용된 호출 환경이 없으면 평가 준비·기준 출력 검사까지만 수행하고 실제 모델 평가는 미실행으로 남긴다. 제공자·전송·비용을 임의 결정해 호출하지 않는다.

## 결과

변경 의미·파일, 프롬프트/스키마/사례 버전, 실행·종료 결과, 데이터 출처, 사람 검토와 실제 모델 평가의 수행 여부를 남긴다. 원문·전체 출력·키가 든 로컬 파일은 커밋하지 않는다.

# Astra에 전달할 틈길 구현 요청

이 문서는 개발 에이전트용 요청이다. 앱에서 의견을 정리하는 [AI 고정 지침](opinion-draft.system.md)과는 별개다. 아래 요청은 **현재 로컬 프로젝트를 열고 모델을 GPT-6 Astra로 선택한 채팅**에 전달한다. 현재 서비스 기반·준비 자료에는 아직 커밋하지 않은 변경이 있으므로 원격 저장소만 새로 복제한 환경과 같지 않다.

짧게 시작하려면 다음 문장을 보낸다.

```text
docs/prompts/ASTRA_BUILD.md의 '구현 요청'을 읽고, 현재 로컬 변경을 보존하면서 요청된 MVP를 구현·실행·검증까지 끝내 줘.
```

## 구현 요청

이 프로젝트의 틈길 MVP를 기존 서비스 기반에서 끝까지 구현해 줘. 목표는 로컬솔루션데이에서 제품의 흐름과 완성도를 설득력 있게 시연하는 것이다. 속도보다 일관된 UX·정확한 저장·권한·모션 마감을 우선한다. 수상이나 현장 효과를 보장하는 문구는 만들지 않는다. 한국어로 작업하고, 첫 화면·일부 API·계획서만 만든 상태에서 작업을 끝내지 않는다.

### 시작할 맥락

먼저 AGENTS.md, Git 변경, README.md를 확인한다. 현재 Next.js·TypeScript·Drizzle·PostgreSQL·Better Auth 기반과 미커밋 작업을 보존하며 이어서 구현한다. 로컬 PGlite는 개발용이며 공유 서비스의 PostgreSQL을 대체하지 않는다. 의존성·현재 동작은 실제 파일로 확인하고 필요 없는 초기화·전면 재생성은 하지 않는다.

[승인된 구현 범위](../design/IMPLEMENTATION_SCOPE.md)와 [PLANS](../PLANS.md)를 읽는다. 사용자는 2026-10-29 권고안 전체를 이번 MVP 기준으로 채택했다. 장보기·상태·공개·첨부·역할 정책을 다시 선택받지 않는다. 남은 외부 서비스·실제 자료 수집 정책과 구분한다.

작업할 부분에 따라 다음 자료를 읽는다. 모든 설치 스킬·원문·과거 회고를 시작부터 한꺼번에 읽지 않는다.

### 만들어야 할 제품

S01–S13과 가입·로그인을 실제 URL·서버 저장으로 연결한다. 시민은 시장·점포를 찾고 재료를 담아 체크하며, 선택적으로 의견을 작성·검토·제출하고 본인 의견을 다시 읽는다. 배정된 운영자는 확인·추가 질문·최소 전달·결과 게시·후속 확인을 수행한다. 연결된 상인은 받은 전달에 입장과 대안 또는 대안 없음을 답한다. 별도 계정에서 같은 의견·전달 ID로 연결돼야 한다.

가입·로그인·로그아웃·세션 만료·접근 거부와 원래 행동으로 복귀하는 흐름도 완성한다. 역할·시장·점포 연결을 부여·회수하는 서버 관리 명령과 감사 기록을 구현한다. 계정·권한을 우회하는 시연 스위치를 만들지 않는다.

장보기는 승인된 공통 목록·정규화 중복 방지·이름 변경·순서 정책을 따른다. 의견 원문·초안·질문·응답·전달·상인 답변·시민용 게시·상태·이력은 각각의 계약을 구현한다. 중복 제출, 재시도, 응답 순서 역전, 동시 수정은 서버와 클라이언트 양쪽에서 다룬다. 저장 결과를 모르는 상황은 성공으로 추정하지 않는다.

사진은 승인된 선택 첨부 계약을 구현한다. 실제 디코딩·메타데이터 제거·자원 상한·비공개 저장·다운로드 권한을 검증한다. 시민·상인·운영자별 API 반환 필드를 제한하고 다른 대상 ID를 넣는 요청을 검사한다. 숨김 UI나 프롬프트를 보안 근거로 삼지 않는다.

외부 AI·지도·메일 키가 없다면 이미 승인된 직접 작성·점포 목록 경로로 전체 흐름을 완성한다. 실제 AI·지도·메일의 성공을 가짜 응답으로 표시하지 않는다. 실제 키가 준비된 연동은 제공자의 현재 공식 문서와 사용 권한을 확인해 연결하고 검증한다. 실제 시민 자료 수집·유료 호출·배포가 필요하면 해당 실행 범위만 확인하고 다른 구현은 계속한다.

### 화면과 모션의 품질

화면별 공개 참고 자료를 실제로 보고, 참고한 패턴과 틈길에 맞춘 차이를 구현에 반영한다. 토스의 검색·행·입력·피드백을 공통 언어로 쓰고 따뜻한 배경과 청록색을 출발점으로 삼는다. 금융 서비스의 로고·문구·그래픽을 복제하지 않는다. 역할별로 정보 밀도는 달라도 글자·간격·상태·오류의 언어는 하나로 만든다.

공통 토큰·입력·버튼·행·패널·상태·타임라인을 먼저 실제 컴포넌트로 정리하고 화면에 적용한다. 공식 DESIGN.md가 아직 없다는 이유로 문서 정리만 하다가 끝내지 않는다. 사용자 승인 방향과 기존 초안으로 구현을 진행하고, 실제 선택한 디자인과 검증 결과를 기록한다. 설치 도구의 제안을 제품 정책의 새 승인으로 해석하지 않는다.

장보기 체크, 원문→검토→접수, 전달→답변→게시의 세 흐름을 특히 세밀하게 다듬는다. 모션 계약의 pending·실패 복구·중단·동작 줄이기·초점 이동을 함께 구현한다. 가짜 진행률·타이핑·성공 효과를 넣지 않는다. 실제 데이터가 없는 사진·평점·성과·재고·지도는 생성해 채우지 않는다.

정상 화면에 더해 빈 목록·읽기 실패·저장 실패·권한 없음·미확인 정보·긴 한글을 설계한다. 모바일 키보드·하단 안전 영역·200% 글자 확대를 확인한다. 필요한 라이브러리와 브라우저 도구는 설치해도 좋으며, 호환 버전·잠금 파일을 관리한다. 모션이 필요한 작은 경계만 클라이언트로 두고 전체 서버 화면을 불필요하게 클라이언트화하지 않는다.

### 완료와 검증

구현 계획은 내부 진행에 사용하고 사용자에게 매 단계 승인을 받느라 멈추지 않는다. 현재 권한 안의 되돌릴 수 있는 구현·도구 설치·수정·검증은 계속한다. 작업 도중 중요한 발견과 남은 문제를 짧게 알린다. 첫 구현 뒤 실제 실행·검사·수정이 남아 있으면 같은 작업을 계속한다.

다음 결과가 확인될 때 인수인계한다. 실패·환경 제한은 통과로 바꾸지 않고 영향과 필요한 조치를 명시한다.

- S01–S13·인증이 실제로 연결되고 A1–A7 및 화면 인수 조건의 구현·실행 근거가 대응된다. 조건을 코드와 무관한 체크표로만 채우지 않는다.
- 서로 다른 실제 세션의 시민·운영자·상인이 같은 의견을 처리하고 새로고침 뒤 저장·공개 범위가 유지된다. 다른 시민·점포·시장과 비로그인 요청의 직접 API 접근을 거부한다.
- `npm run verify`와 배포 빌드가 통과한다. 추가한 핵심 저장·권한·첨부·상태·중복·충돌 경로의 의미 있는 테스트가 있다. 공유 PostgreSQL에서도 검증하고 PGlite 결과와 구분한다.
- Playwright로 핵심 여정을 수행하고 320·390·768·1440px 화면을 직접 관찰한다. 자동 접근성 검사에 더해 키보드·초점 복원·200% 확대·일반/줄인 모션·느린 응답·실패를 검사한다. 시각·모션은 스크린샷과 trace 등 실제 근거를 남긴다.
- 재현 가능한 가상 시드·독립 역할 계정 준비·초기화 명령·시연 절차가 있다. 실제 이용자·협력·효과로 오인되는 자료가 없다. 브라우저 콘솔·서버 오류와 깨진 이동이 정리됐다.
- README·개발 안내·진행 기록을 최종 구현과 맞춘다. 실제 실행 명령, 구현 범위, 검사 결과, 미연동·미검증 범위와 남은 결정이 명확하다. 키·환경 파일·개인 원문·사진·브라우저 세션·민감한 trace는 커밋하지 않는다.

기존 루트 `src/app/route.ts`는 API 기반 확인용 응답이다. 홈 `page.tsx`를 만들 때 같은 경로의 충돌을 정리한다. 완료 후 검사를 이유 없이 반복하지 않으며 새로운 실패·변경에 맞춰 필요한 검사를 수행한다. 커밋·푸시·배포는 이 구현 요청에 포함하지 않는다.

## 작성 근거와 한계

완료 범위와 후속 검증까지의 권한을 명확히 하고 문서는 필요할 때 찾아 읽도록 구성했다. [OpenAI의 Astra 프롬프트·스킬 안내](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)와 [Astra 가이드](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)를 참고했다. 이 문서 작성만으로 Astra의 실제 구현 결과나 대회 성과를 검증한 것은 아니다.

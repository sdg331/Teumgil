# 틈길 제품 기준과 화면 명세

이 문서는 **무엇을 만들어야 하는가**의 기준이다. 현재 구현 여부는 [README](../README.md), 데이터·권한·처리 상태는 [DATA_ACCESS](DATA_ACCESS.md), 선택이 필요한 사항은 [PLANS](PLANS.md)에서 관리한다. 아래 화면 동작과 인수 기준은 구현할 설계이며, 이미 동작하는 앱의 설명이 아니다.

## 제품 목적과 범위

시민이 전통시장의 점포와 품목을 찾고 장보기 목록을 만든다. 통행 불편이 있으면 선택적으로 의견을 남긴다. 틈길 운영자는 내용을 확인하고 관련 상인의 입장과 대안을 듣고, 확인된 결과와 후속 확인을 기록한다.

중심은 현장의 확인·협의·유지관리다. 시장지도와 장보기는 일상 이용을 돕는다. 발표에서 보여 줄 부분은 [시연 시나리오](DEMO_SCENARIO.md)에서 고르며, 그 선택이 전체 제품의 기능을 대체하지 않는다.

## 변경 시 보존할 제품 기준

| ID | 기준 | 구현에서 확인할 결과 |
| --- | --- | --- |
| R1 | 시장 이용과 의견 작성은 별개로 선택한다 | 메뉴 선택·의견 제출 없이 점포 검색과 재료 입력 가능 |
| R2 | 틈길 접수는 내부 의견이다 | 공식 신고 경로가 내부 상태와 독립적이며, 공식 접수·처리 현황을 임의 생성하지 않음 |
| R3 | 점포·상황에 관한 정보는 근거 범위에서 표시한다 | 평소 취급 품목의 출처·확인일, 미확인 재고·가격 표시. 물건 소유·책임·위법성·실제 효과를 추측하지 않음 |
| R4 | 초안은 이용자가 검토한다 | 원문과 초안을 비교·수정하고 직접 제출. AI 실패 시 직접 작성 가능 |
| R5 | 상태·협의는 확인 기록에 연결한다 | 담당 주체·시각·사유, 미해결 사유와 필요 시 후속 확인 계획을 남김. 조치 확인을 완전 해결로 표현하지 않음 |
| R6 | 참여와 정보 공유는 당사자 동의와 관련 범위를 전제로 한다 | 상인에게 매일 재고 입력을 강제하거나 원문·사진을 일괄 공개하지 않음. 동의 없는 물품 이동·폐기·단속을 자동화하지 않음 |
| R7 | 구현과 사실의 출처를 드러낸다 | 가상 자료·시연 계정·템플릿을 구분. 상인회·지자체 협력, 현장·매출·행정 효과는 확인 전 가설로 표시 |
| R8 | 거래·유료 노출은 별도 범위다 | 장바구니를 결제·배송으로 표현하지 않음. 유료 홍보를 한다면 광고로 표시하고 의견 처리 순서와 분리 |

의견 AI가 지킬 세부 출력 규칙은 [프롬프트와 스키마](prompts/README.md)에 있다. 즉각적인 긴급 위험의 119·112 안내와 공식 경로는 AI 응답이나 운영자 확인을 기다리게 하지 않는다.

## 화면과 진입

화면 작업은 아래에서 대상 ID를 정하고 **해당 상세 명세와 [공통 기준](screens/COMMON.md)**을 읽는다. 이 문서는 제품 규칙·전체 범위와 화면 목록을 소유하고, 상세 명세는 영역·입력·클릭·예외·화면별 인수 조건을 소유한다. 데이터·권한·상태 정의를 상세 화면에 다시 만들지 않는다.

ID를 추가·이동·폐기할 때는 [ID 관리 규칙](ID_POLICY.md)과 [할당 대장](spec-ids.json)을 함께 갱신한다. 표시 순서가 바뀌어도 기존 번호는 유지한다.

| ID | 화면 | 진입·주요 이동 | 상세 명세 |
| --- | --- | --- | --- |
| S01 | 홈 | 앱 시작·홈 탭 → 시장지도·장바구니 | [시장 탐색](screens/DISCOVERY.md) |
| S02 | 시장지도·점포 목록 | 시장 선택·탭·관련 점포 찾기 → S03·S05 | [시장 탐색](screens/DISCOVERY.md) |
| S03 | 점포 상세 | 점포 선택 → S04 또는 이전 탐색 | [시장 탐색](screens/DISCOVERY.md) |
| S04 | 장바구니 | 탭·이어보기·점포 상세 → S02·S03 | [장보기](screens/SHOPPING.md) |
| S05 | 의견 작성 | S02 알리기 → S06 | [의견 작성·제출](screens/OPINION_SUBMISSION.md) |
| S06 | 원문·초안 검토와 제출 | S05 → 저장 성공 시 S07 | [의견 작성·제출](screens/OPINION_SUBMISSION.md) |
| S07 | 내부 접수 결과 | 실제 저장 성공 → S09·S02 | [의견 작성·제출](screens/OPINION_SUBMISSION.md) |
| S08 | 마이·내 의견 목록 | 마이 탭 → S09 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |
| S09 | 시민 의견 상세 | S08·S07 → 본인 기록·추가 질문 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |
| S10 | 운영자 의견 목록 | 운영자 진입 → S11 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |
| S11 | 운영자 의견 상세·처리 | S10 → 확인·전달·결과 기록 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |
| S12 | 상인 전달 목록 | 상인 진입 → S13 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |
| S13 | 상인 전달 상세·답변 | S12 → 본인 전달에 답변 | [의견 조회·처리](screens/OPINION_OPERATIONS.md) |

시민 하단 탭 순서는 **홈 · 시장지도 · 장바구니 · 마이**다. 실제 경로는 구현에서 정한다. 계정·역할은 승인된 데이터 계약을 따르며 시연도 별도 계정을 사용한다. 실제 지도가 없으면 가상 도식임을 표시하고 목록으로도 점포를 찾을 수 있게 한다.

메뉴·AI 추천, 냉장고, 저장 점포, 알림과 POS 등은 확장 후보다. 핵심 흐름 구현 요청에 자동 포함하지 않는다.

## 기능별 동작과 예외

| 기능 | 입력 → 결과 | 예외에서 유지할 것 |
| --- | --- | --- |
| 점포 검색 | 시장·품목 검색어 → 일치하는 점포와 평소 품목·출처·확인일 | 결과가 없으면 검색어 수정. 재고 확인처럼 보이지 않게 함 |
| 장보기 | 재료명 → 목록 항목. 체크·이름 수정·삭제 → 해당 항목 변경 | 빈 목록에 재료 입력 안내. 중복 정책은 승인된 S04·D2 기준 적용 |
| 의견 작성 | 위치·상황, 알고 있는 발견 시점, 선택 사진 → 작성 내용 | 시점 미입력을 임의 날짜로 보충하지 않음. 사진은 선택 |
| 초안 검토 | 이용자 원문 → 정리 초안 또는 직접 작성 | 생성 실패 시 원문 유지. 원문에 없는 요청을 추가하지 않음 |
| 내부 제출 | 이용자 확인·제출 → 저장된 의견과 접수 결과 | 실패 시 성공 표시 금지. 입력과 재시도 경로 유지 |
| 의견 상세 | 의견 ID → 본인에게 공개 가능한 현재 상태·이력 | 내부 메모·다른 사람의 사진을 자동 노출하지 않음 |
| 확인·협의 | 같은 의견에 확인·전달·답변·결과 기록 | 상태·공개 범위의 임의 전이 금지. 계약은 DATA_ACCESS 참고 |

**입력 검증 제안:** 접수 시 위치 선택 또는 설명과 공백이 아닌 상황 설명을 받는다. 발견 시점과 사진은 선택이다. 첨부는 승인된 D5 기준, 문자열 길이는 서버와 폼에서 같은 구현 상한을 사용한다. AI의 `missing_fields`는 폼의 필수 입력 판정이 아니다.

상세 명세의 Sxx-Tn은 아래 A1–A7을 화면 행동으로 세분한 검증 조건이다. 조건의 정의와 실행 결과는 구분한다. 현재 URL·API·DB와 조건별 실행 근거는 [MVP 인수 기록](MVP_VERIFICATION.md)에서 확인한다.

## 인수 시나리오

일회성 발표 자료가 아니라 기능 변경 후 결과를 확인할 시나리오다. 실제 앱을 만들면 아래를 동작 검사로 연결한다.

| ID | 시작 조건·행동 | 통과할 결과 |
| --- | --- | --- |
| A1 | 평소 대파 취급 정보가 있는 점포 검색 후 장보기 추가 | 해당 점포를 찾고 목록 항목 생성. 당일 재고·가격은 추정하지 않음 |
| A2 | 위치·상황 입력, 시점·사진 없이 초안 검토 후 제출 | 선택 필드를 강제하지 않고 저장 성공 시 내부 접수. 생성만으로 제출되지 않음 |
| A3 | 초안 생성 또는 저장 실패 | 원문 유지, 직접 작성·재시도 가능. 거짓 성공 표시 없음 |
| A4 | 한 의견을 운영자가 확인·전달하고 관련 상인이 답변 | 의견·전달 ID로 같은 기록에 연결. 무관한 상인에게는 노출되지 않음 |
| A5 | 조치 또는 미해결 사유와 후속 계획 기록 | 확인 사실·시각·사유 표시. 예정과 실제 수행 구분 |
| A6 | 내부 처리 대기 중 공식 경로 선택 | 틈길 상태를 바꾸거나 운영자 승인을 기다리지 않고 별도 경로 이용 |
| A7 | 좁은 화면·키보드·빈 결과·읽기 실패 | 이름표·초점·오류 설명과 다음 행동 확인 |

화면의 색상·간격은 [디자인 초안](DESIGN_DRAFT.md), 문구는 [UX_COPY](UX_COPY.md)를 참조한다. 재고·공식 처리·초안 상태의 의미를 문구 수정만으로 바꾸지 않는다.

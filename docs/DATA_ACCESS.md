# 틈길 데이터·권한·처리 계약

2026-10-29 사용자 승인 MVP 정책을 반영했다. 이 문서는 데이터와 권한의 구현 기준이며, 구현 완료 기록은 아니다. 화면 행동은 [제품 명세](PRODUCT_SCREENS.md), 채택 근거·남은 결정은 [PLANS](PLANS.md)에서 관리한다.

## 연결 관계와 저장 원칙

한 의견 ID에 초안·첨부·질문·전달·답변·결과·이력을 연결한다. 역할별 복사본에 별도 상태를 유지하지 않는다. 원문은 초안으로 덮어쓰지 않으며 AI 출력은 실행 명령이 아니다.

| 기록 | 필요한 연결·정보 | 구분할 것 |
| --- | --- | --- |
| 시장·점포 | 시장 ID, 점포 ID, 평소 품목, 출처·확인일, 가상 여부 | 평소 품목과 당일 재고·가격 |
| 장보기 | 계정 소유 목록·항목 ID, 이름, 체크, 생성 순서 | 주문·결제와 목록. 상세 정책은 [S04](screens/SHOPPING.md) |
| 의견 | 작성 계정, 시장, 위치·상황 원문, 선택 발견 시점, 제출 시각, 현재 상태 | 발견 시점과 제출 시각 |
| 초안 | 원문 연결, 생성 방식, 정리 내용, 이용자 편집 내용 | AI의 draft/needs_input/out_of_scope와 처리 상태 |
| 첨부 | 의견·작성자, 검증된 이미지, 형식·크기, 처리 상태 | 업로드 성공과 제출 성공 |
| 추가 질문·응답 | 의견·질문 ID, 작성자, 내용·시각 | 새 응답과 원문 정정 |
| 상인 전달 | 의견·전달 ID, 대상 점포·상인, 관련성 근거, 전달용 요약·위치, 시각 | 가까운 점포와 관계가 확인된 상인 |
| 상인 답변 | 전달 ID, 답변자·시각, 입장, 대안 또는 대안 없음 | 답변과 상태 변경·시민 공개 |
| 시민용 게시 | 의견, 운영자가 작성한 확인 요약·결과, 게시자·시각, 정정 연결 | 내부 메모·상인 원문과 시민용 내용 |
| 처리 이력 | 의견, 행동, 변경 전후 상태, 주체·시각·사유, 정정 연결 | 현재 상태와 과거 과정 |
| 후속 확인 | 의견, 담당자, 예정 시점, 실제 시각·결과 | 계획과 실제 수행 |

식별자·시간·버전 등 물리 필드는 기존 PostgreSQL·Drizzle 기반에서 구체화한다. 상태 변경·결과·이력은 같은 트랜잭션으로 저장한다. 중복 제출 방지와 동시 수정 충돌은 서버에서 검증하며 실패를 성공으로 표시하지 않는다.

## 역할과 열람 범위 · D4·D7

회원가입의 초기 역할은 citizen이다. 운영자는 배정된 시장, 상인은 연결된 점포로 대상을 제한한다. 역할·시장·점포 연결은 신뢰된 서버 관리 명령으로 부여·회수하고 변경 주체·시각·사유를 기록한다. 클라이언트 입력·URL·역할 선택 UI는 권한의 근거가 아니다.

| 자료·행동 | 작성 시민 | 관련 상인 | 담당 운영자 | 일반 공개 |
| --- | --- | --- | --- | --- |
| 공개 가능한 시장·점포 정보 | 로그인 없이 읽기 | 읽기 | 읽기 | 가능 |
| 장보기 목록 | 본인만 | 본인 목록만 | 타인 목록 접근 없음 | 불가 |
| 의견 원문·사진 | 본인만 | 불가 | 배정 시장의 업무 범위 | 불가 |
| 상인 전달 요약·위치 | 자동 공개 없음 | 본인에게 전달된 건만 | 담당 건 | 불가 |
| 상인 답변 원문 | 불가 | 본인 답변만 | 담당 건 | 불가 |
| 내부 메모·관계 판단 | 불가 | 불가 | 담당 범위 | 불가 |
| 시민용 질문·게시·이력 | 본인 건만 | 자동 접근 없음 | 담당 건 | 불가 |
| 상태·결과·시민용 게시 변경 | 불가 | 불가 | 승인된 행동만 | 불가 |

조회 API는 역할별 반환 필드를 따로 구성한다. 전체 의견 객체를 보내 UI에서 숨기는 구현은 허용하지 않는다. 대상 ID를 추측해도 서버가 소유·배정·전달 관계를 검사한다. 로그인하지 않은 요청은 인증 실패, 타인의 비공개 대상은 존재를 드러내지 않는 응답을 일관되게 사용한다.

이메일·비밀번호와 DB 세션은 기존 Better Auth를 유지한다. 이메일 소유 확인·재설정은 실제 메일 연동 전에는 발송·확인 완료로 표시하지 않는다. 시연은 서로 다른 가상 계정을 별도 브라우저 세션에서 로그인한다.

## 행동별 계약

| 행동 | 실행 주체·전제 | 남길 결과 | 실패·거부 조건 |
| --- | --- | --- | --- |
| 제출 | 시민이 원문·내용 확인 후 제출 | 의견·제출 시각·received 이력 | 입력 부족·저장 실패·결과 미확인에서 접수 성공 금지 |
| 확인 시작 | 배정된 운영자 | 확인 기록·상태·이력 | 관계·전이 검사 실패 |
| 추가 질문·응답 | 운영자가 질문, 해당 시민이 응답 | 질문에 연결된 새 기록 | 응답만으로 자동 상태 변경 금지 |
| 상인 전달 | 운영자가 관련성 근거·대상·공개 범위 확인 | 새 전달 ID·요약·위치·시각 | 근거·대상 불명확, 원문·사진·개인정보 자동 포함 |
| 상인 답변 | 해당 전달을 받은 상인 | 입장·대안 또는 대안 없음·시각 | 다른 전달 ID, 자동 시민 공개·상태 변경 |
| 시민용 게시 | 운영자가 별도로 확인 요약·결과 작성 | 미리보기 후 게시 기록 | 상인 원문 일괄 공개, 확인하지 않은 해결 단정 |
| 결과·상태 변경 | 담당 운영자가 근거 또는 미확인 사유 보유 | 결과·상태·이력의 원자적 저장 | 전이 위반·근거 없음·저장 충돌 |
| 재개·정정 | 담당 운영자가 사유 기록 | 새 이력 또는 정정 연결 | 기존 원문·답변·이력의 조용한 덮어쓰기 |
| 후속 확인 | 담당자가 계획·수행 구분 | 예정 또는 실제 수행 결과 | 계획만으로 완료 표시 |

전달 전 대상과 실제 전달 내용을, 게시 전 시민에게 보일 내용과 대상을 미리 보여 준다. 재전달은 새 전달 ID로 만들며 기존 기록을 보존한다. 답변의 정정은 이전 답변을 연결하는 새 기록으로 남긴다. 제출 후 원문·이력 삭제 UI는 이번 MVP 범위에 포함하지 않는다. 실제 자료의 삭제·보관 정책은 별도 결정한다.

## 상태와 독립 이벤트 · D3

| 코드 | 표시 이름 | 필요한 기록 |
| --- | --- | --- |
| received | 틈길 접수 | 제출 시각 |
| verifying | 확인 중 | 확인 주체·내용 |
| needs_info | 추가 정보 필요 | 시민용 질문·시각 |
| consulting | 협의 중 | 관련성 확인·상인 전달 |
| action_confirmed | 확인된 조치 있음 | 무엇을 언제 확인했는지 |
| unresolved | 확인 불가 / 대안 미확보 | 확인하지 못한 내용 또는 대안 미확보 사유 |

unresolved는 하나의 상태다. **공식 신고 안내는 독립 이벤트**로 안내 내용·시각을 남기며 이 여섯 상태를 덮어쓰지 않는다. 내부 접수·공식 신고·긴급 위험 안내는 별개다.

| 현재 코드 | 허용되는 다음 코드 | 운영자 행동의 조건 |
| --- | --- | --- |
| received | verifying | 확인 시작 기록 |
| verifying | needs_info, consulting, action_confirmed, unresolved | 각각 질문, 전달 근거, 확인 사실, 미확인 사유 |
| needs_info | verifying, consulting, unresolved | 응답 검토 또는 확인할 수 없었던 사유 |
| consulting | verifying, needs_info, action_confirmed, unresolved | 행동에 맞는 확인·질문·결과 근거 |
| action_confirmed, unresolved | verifying | 담당 운영자의 재개 사유 |

모든 상태를 순차 진행 단계로 표시하지 않는다. 시민·상인의 응답은 독립 기록이며 상태를 자동으로 바꾸지 않는다. 시민에게 보일 이력 내용은 위 공개 계약을 따른다.

## 첨부 · D5

사진은 선택이며 JPEG·PNG·WebP 원본 파일당 2MiB, 의견당 최대 3개를 허용한다. 서버에서 실제 디코딩·이미지 크기 검증·메타데이터 제거 후 비공개 PostgreSQL 첨부 테이블에 저장한다. 디코딩 자원 상한과 오류는 구현에서 정하고 검증한다. 확장자나 MIME만으로 파일을 신뢰하지 않는다.

공개 파일 URL을 만들지 않는다. 다운로드마다 본인 시민 또는 담당 운영자의 관계를 검사한다. 상인에게 사진을 전달하지 않으며 AI 초안 생성에도 자동 전송하지 않는다. 제출 전 실패·제거·텍스트만으로 계속하기를 지원한다.

이번 MVP 검증에는 가상 자료를 쓴다. 실제 시민 자료 수집, 보관 기간·삭제·동의 정책과 production 운영 승인은 별도다. 이 승인으로 실제 수집·배포를 시작하지 않는다.

## 변경 검증

- 같은 의견·전달 ID를 역할별로 읽고 허용 필드만 반환하는가?
- 비로그인·다른 시민·무관한 상인·다른 시장 운영자의 직접 API 요청을 거부하는가?
- 상인 답변·시민 응답·공식 안내가 자동 상태 변경이나 자동 공개를 일으키지 않는가?
- 상태·결과·이력 저장 실패와 동시 변경에서 불일치·중복이 남지 않는가?
- 사진의 형식 위장·크기 초과·개수 초과·무권한 다운로드를 차단하는가?
- 재개·정정·재전달의 원래 기록과 사유를 보존하는가?

제품의 R1–R8은 [제품 명세](PRODUCT_SCREENS.md)를 따른다. 이 문서의 채택은 실제 권한·저장·첨부 검증 완료를 의미하지 않는다.

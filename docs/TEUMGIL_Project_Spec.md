# 틈길 전체 제품 기획과 개발 인수인계

> 기준일 2026-10-28 · 작성 목적: 팀과 Codex가 같은 맥락에서 결승 시연 및 이후 개발을 논의하기 위한 기획 초안. 현재 웹앱과 실제 운영이 완성됐다는 뜻이 아니다.

## 1. 프로젝트 한눈에 보기

- 팀: 길이음. 프로젝트: 틈길(TEUMGIL).
- 기존 출품명: 전통시장 보행·영업 공간의 상생을 위한 참여형 골목 관리 솔루션.
- 목표: 시민과 상인이 같은 시장 공간을 사용하는 과정에서 불편이 발생했을 때, 의견 접수부터 현장 확인, 상인과의 협의, 결과와 유지 확인까지 이어지도록 돕는다.
- 새로 논의한 방향: 시장지도와 장보기는 평소 이용 동기를 돕고, AI는 이용자의 말에서 공식 민원이나 내부 의견 작성용 초안을 정리한다.
- 핵심은 앱 자체가 물건을 치우는 것이 아니라 **현장의 확인·협의·조정과 유지관리**를 돕는 것이다.

### 사실과 아이디어의 구분

| 구분 | 내용 |
|---|---|
| 확인된 사실 | 2026-03-09 구로구가 개봉중앙골목시장 인근 개봉로17길 14 주변의 적치물 정비를 발표했다. 팀장 방문 당시 적치물이 두드러지지 않았다. |
| 현재 구상 | 한 앱의 시장지도·장보기·의견 알리기, AI 초안, 운영자 확인과 상인 협의를 연결한다. |
| 검증할 가설 | 시민이 시장 정보를 반복 이용하고, 상인이 점포 노출이나 의견 조정에 가치를 느끼며, 운영 기록이 업무에 도움이 된다. |
| 미확인 | 현재 시장 전체의 문제 규모·빈도, 상인의 참여·지불 의사, 장기 운영 주체, 공무원 업무 감소, 공공기관·POS 연동, 특허 가능성. |

시장 전체의 현재 문제를 과거 한 장소의 정비 사례로 일반화하지 않는다. 날씨나 계절을 관찰 결과의 원인이라고 단정하지 않는다.

## 2. 대회 배경과 기존 기획

- 미션 1은 로컬실록지리지에 지역문제를 게시, 미션 2는 PSST 기반 해결방안 기획서를 제출하는 것이다. 게시물: https://scoutedu.kr/localHeroes/problem/2375
- 2026-10-18 제출한 자료에서 확인된 최초 주제는 보행·영업 공간 상생이다. 결승에는 6개 팀이 참여한다.
- 발표영상은 **7분 이내**, 제출기한 **2026-11-13**, 제출처 **khchun2@uc.ac.kr**. 피드백 반영이 필요하고 기한 미제출 시 탈락 안내가 있었다.
- 기존 기획서는 통행환경 진단 → 상인 협의 → 개선 전후 비교와 7일 후 재확인 → 결과 공유에 초점을 둔다. 4주 실증, 자발적 인터뷰, 잠정 목표치 등은 **당시 계획**이다. 실험 결과가 아니다.
- 최신 대화에서는 바쁜 상인과 대면 인터뷰가 어렵다는 제약에 맞춰 2주 소규모 실증을 제안했다. 4주를 공식적으로 바꾼 것이 아니며 실증 기간·방법은 미확정이다.
- 기존 기획은 상권 운영 주체 대상 B2B 모델을 우선 검토했다. 최근 논의에서는 무료 기본 등록 및 상인의 선택형 홍보라는 수익 가설을 추가했다. 선택형 홍보가 기존 BM의 검증 부족을 자동 해결하지는 않는다.
- 장보기 추가가 결승에서 기존 출품작의 허용되는 발전 범위인지는 주최 측에 아직 확인되지 않았다.

## 4. 이용자와 참여 구조

### 일반 시민·시장 고객
- 시장지도에서 점포와 통상 취급 품목을 살펴보고, 재료를 장보기 목록에 담는다.
- 통행 불편을 겪었다면 위치·상황을 작성하고, 선택적으로 사진을 첨부한다. 신고를 원하지 않으면 알리기를 건너뛸 수 있다.
- 모든 고객이 제보할 것으로 가정하지 않는다. 앱 이용 수가 적거나 제보가 없다는 사실을 현장에 문제가 없다는 근거로 사용하지 않는다.
- 자신의 작성 내용과 틈길 내부 처리 기록, 알림과 공지를 마이에서 확인한다.

### 상인
- 일반 고객 화면을 사용할 수 있고, 점포를 확인한 계정에는 가게 관리 기능을 추가하는 방안이다.
- 동의한 기본 점포 위치·소개·평소 취급 품목을 확인하거나 수정을 요청한다. 매일 재고 등록은 필수가 아니다.
- 운영자가 확인해 전달한 의견에 대해 본인의 물건이 아니거나 보관 공간·시간·인력·영업상 어려움이 있다는 입장을 설명할 수 있다.
- 상인 참여·점포 정보 게시·현장 조정은 자발적 동의와 실제 조건을 전제로 한다. 노출 효과와 진열 변경 이익을 보장하지 않는다.

### 틈길 운영자
- 초기에는 길이음팀이 제한된 시범 구간을 운영하는 안이다. 아직 상인회나 지자체의 운영·협력이 약속된 것은 아니다.
- 접수 위치와 원문을 확인하고 필요하면 추가 질문한다. 특정 점포나 물건의 소유·불법 여부를 자동 판단하지 않는다.
- 관련이 확인되고 필요한 범위에서만 상인에게 전달하고 의견과 실행 가능 대안을 기록한다.
- 정기 확인 담당자·수행 가능 시간·부재 시 대응·안전·물건 소유와 관리 권한을 확인한다. 물품을 동의 없이 이동·폐기하거나 단속하지 않는다.
- 대응이 불가능하면 보류·대안 없음으로 기록하고 이용자에게 공식 창구 이용 방법을 안내한다.

### 공무원·공공기관
- 틈길 운영자와 공공기관 담당자는 서로 다르다. 공무원 계정, 전용 대시보드, 업무 시스템 연동은 확정되지 않았다.
- 시민이 공식 창구에 직접 제출한 민원은 해당 기관이 처리한다. 틈길의 요약이나 링크만으로 접수·담당 부서 지정·업무시간 감소가 발생한다고 표현하지 않는다.

## 5. 이용자 경험과 하단 탭

### 정보 구조
- 홈: 시장 검색, 메뉴 추천, 장보기 이어보기, 주요 공지. AI 메뉴 추천은 선택적이며 구현 범위 미확정.
- 시장지도: 점포·품목 탐색과 위치 선택, `+ 알리기`. 실제 지도가 없다면 가상의 시장 도식임을 표시.
- 장바구니: 살 재료를 적고 관련 점포를 찾는다. 실제 주문·결제·배송이 아니다.
- 마이: 냉장고 재료와 저장 점포, 내가 남긴 의견, 알림, 시장 공지. 상세 기능의 구현 범위는 단계별로 정한다.
- 로그인 없이 지도·점포·공지 둘러보기는 제안 사항. 실제 저장 기능과 공식 신고의 인증은 별도 설계한다.

### 장보기 흐름
1. 메뉴를 고르거나 재료를 직접 검색한다. 메뉴 선택을 강제하지 않는다.
2. 집에 있는 재료를 제외하거나 장보기 목록을 만든다.
3. 점포의 평소 취급 품목·위치·출처·확인일을 본다.
4. 당일 재고·가격을 모르면 `재고 미확인`, `가격 미확인`으로 표시한다. AI가 임의로 재고와 점포를 만들어내지 않는다.
5. 거래·결제·배송·점포 방문·매출은 앱에서 자동으로 이뤄진다고 가정하지 않는다.

### 점포 정보의 경계
- 출처 후보: 상인 확인, 운영자 확인, 적법하게 이용할 수 있는 자료. 실제 수집 방법·동의·갱신 주기·삭제 처리 미확정.
- 정보가 오래됐거나 충돌하면 검토 필요를 표시한다. 고객의 제보는 확인 전 사실로 확정하지 않는다.
- 키오스크/POS API 연결은 추후 협력과 각 기기 제공 범위 확인이 필요한 확장 아이디어다. 기기가 있다는 사실만으로 재고를 알 수 없다.

## 6. 의견 작성과 AI 초안

### 기본 입력 필드 제안
위치(지도 선택·설명), 발견 시점(알고 있으면), 상황 설명, 선택 사진. 이는 틈길의 **내부 정보 구조 제안**이며 공공기관 공통 법정 서식이 아니다.

### AI 역할과 제한
- 원문의 사실만 사용해 제목·위치·시점·상황·요청의 초안을 만든다. 부족한 항목은 비우고 확인 질문을 제안한다.
- 이용자가 초안과 원문을 비교·수정하고 제출 여부를 결정한다. 불법, 소유자, 반복 빈도, 위험도, 확인하지 않은 날짜·주소를 지어내지 않는다.
- 데모에서는 검증된 예시 또는 결정적 템플릿을 사용해도 된다. 실제 AI 호출을 하지 않는다면 화면과 발표에서 AI 연동으로 소개하지 않는다.
- 실제 생성 AI는 민감 데이터 최소화, 전송 전 고지, 입력 보관·삭제, 실패·시간초과, 재시도 비용, 악의적 지시와 출력 검증, 접근성 및 사용량 제한을 설계한다.

**가상 입력:** “시장 입구에 상자가 있어서 유모차가 지나가기 힘들었어요.”

**가상 초안:** “시장 입구 주변의 상자로 인해 유모차 통행이 어려웠다는 의견입니다. 현장 확인을 요청합니다.”

**추가 확인:** 세부 위치와 발견 시점. 상자 소유자, 위법성, 재발 여부는 알 수 없다.

### 공식 경로
- `틈길에 알리기`: 내부 접수. 공식 민원으로 자동 제출되지 않는다.
- `공식 신고 창구 이용하기`: 사용자가 언제든 국민신문고·안전신문고 등 해당 창구를 열고 유형, 인증, 사진 및 입력 요건을 확인해 직접 제출한다. 틈길 관리자 확인은 선행조건이 아니다.
- 국민신문고 일반민원과 인허가 같은 정형 서식 민원은 구분된다. 안전신문고는 유형별 요건이 다를 수 있다. 모든 공식 입력 필드 또는 사진 요건을 확인했다고 주장하지 않는다.
- 공식 처리 현황은 공식 창구에서 확인한다. 자동 연계가 없으면 틈길에는 사용자가 직접 기입한 정보만 그 출처를 밝혀 표시한다.
- 즉각적 긴급 위험은 틈길 처리를 기다리지 않고 119·112를 이용하도록 안내한다.

## 7. 확인과 협의의 상태 모델 제안

| 상태 | 의미 | 변경 주체 |
|---|---|---|
| 틈길 접수 | 내부 의견을 받음. 공식 민원 아님 | 시스템 |
| 확인 중 | 운영자가 위치·상황 확인을 시작 | 운영자 |
| 추가 정보 필요 | 사실 확인에 필요한 내용을 요청 | 운영자 |
| 협의 중 | 관련 상인의 의견 또는 대안을 확인 | 운영자 |
| 공식 신고 안내 | 이용자에게 공식 경로를 안내 | 운영자 또는 이용자 선택 |
| 확인된 조치 있음 | 무엇을 언제 확인했는지 기록 | 운영자 |
| 확인 불가 / 대안 미확보 | 내용이나 대안을 확인하지 못함 | 운영자 |

상태 라벨과 전이 규칙은 개발 설계 제안이며 미확정이다. 실제 운영에서는 변경 이력과 담당자를 남긴다. `확인된 조치 있음`은 행정상 적법성이나 완전 해결을 보증하지 않는다. 이용자는 별도 경로에서 언제든 공식 신고를 선택할 수 있다.

## 8. 상인 협의의 실제 대안

1. 제보를 받은 뒤 위치·시간·소유자를 먼저 확인한다.
2. 상인이 답변할 수 있다면 보관 공간, 상품 노출, 작업 시간·인력 등의 어려움을 듣는다. 실제 이유를 미리 가정하지 않는다.
3. 관계자의 동의와 허용 범위 안에서 점포 내 보관 위치, 진열 방식, 물품 이동 시간 등 가능한 대안을 검토한다.
4. 대체 공간과 인력은 실제 존재·권한·비용을 확인한다. 없으면 없다고 기록한다.
5. 적용 전후 같은 조건의 현장 상태와 상인 부담을 관찰하고 다시 확인한다.

해당 과정은 상인의 부담을 줄일 가능성이 있는 제안이지 실제 효과가 검증된 개입이 아니다. 무료 점포 소개·유료 광고가 공간 정리의 충분한 보상이라는 근거 역시 없다.

## 9. 사업성과 운영

기본 시민 이용과 점포 등록은 무료로 제공하고 추후 상인이 원할 때 선택형 홍보를 이용하는 가설이다. 유료 노출은 광고로 명시하고 의견 처리 순서·안전 판단과 분리한다. B2G 계약을 수익 전제로 삼지 않는다. 기존 B2B 모델은 별도의 가설로 남겨두며 임의로 유료 전환하지 않는다.

- 매출 후보: 유료 점포 수 × 이용료. 실제 유료 고객·가격·전환율 미검증.
- 비용: 현장 관찰·점포 확인·협의·안전한 운영 인력, 서버·지도·AI 사용료 및 지원 비용.
- 검증: 참여 전후 상인이 겪는 부담, 실제 홍보 가치·지불 의사, 운영 시간과 원가를 따로 기록.
- 제보가 늘거나 준 것만으로 시장 안전·매출 효과를 판단하지 않는다. 공공기관 업무시간 감소도 측정 전 가설이다.

## 10. 시범 운영과 평가 계획

### 결승 전 빠른 검증 제안
- 팀원끼리 가상 의견 1건을 작성하고 운영자·상인 역할을 나눠 처리한다. 누락 정보와 처리 시간을 기록한다.
- 지인 3~5명에게 가상 화면에서 점포 찾기, 의견 작성, 공식 신고와 틈길 접수 구분을 시도하게 한다. 이해하기 어려운 부분을 수정한다.
- 위 검사는 시연의 사용성과 운영 흐름 점검이다. 실제 상인 지불 의사·지역 문제 규모·현장 개선을 증명하지 않는다.

### 향후 현장 시범 제안
참여에 동의한 소수 점포와 일부 구간에서 약 2주 운영하는 최근 제안이 있다. 기간·장소·상인회 협력·참여자·실제 운영은 모두 미확정이다. 기존 출품안은 4주였으므로 대회 규정과 현실에 맞게 팀이 최종 결정한다.

후보 지표: 관찰 구간·시간·조건, 통행 방해 시간, 우회·대기 사례와 전체 통행 대비 비율, 동일 위치의 폭, 7일 뒤 유지 여부, 상인의 추가 작업 시간, 운영자 첫 확인 시간 및 운영비. 사례가 없거나 기준선이 0이면 감소율을 계산하지 않는다. 표본이 작으면 그 한계를 밝힌다. 기존 제출안의 20% 감소는 **잠정 목표**였고 실제 성과가 아니다.

## 11. 결승 시연 범위와 완료 기준

핵심 시나리오: 시장지도·장보기 → 위치와 의견 입력 → 초안 확인·수정 → 내부 접수 → 운영자 확인 → 상인 의견 → 결과 또는 미해결 확인. 내용은 가상 데이터임을 화면에 명확히 밝힌다.

고객·상인·운영자 역할 전환은 데모인지 실제 인증인지 구분한다. 미구현 AI, 외부 민원 연동, 실시간 재고, 키오스크, 상인 협력·매출 상승을 구현·확정된 기능처럼 표현하지 않는다. 실제 접근 권한·데이터 보안이 필요하면 별도 백엔드 구현과 검증이 필수다.

영상은 7분 이내, 2026-11-13까지 제출. 이 문서나 웹앱 시안이 영상 제출 자체를 대신하지 않는다.

## 12. 특허와 공개

레시피 기반 장보기와 냉장고 재료 추천·주문에 관한 유사 특허 문헌이 존재한다. 구체적 기술을 정리하고 선행기술과 청구항을 비교하기 전 특허 가능성·침해 여부를 판단하지 않는다. GitHub, 지역문제 게시물, 출품 및 결승 영상의 공개 내용·시점을 기록하고, 공개 전 변리사·학교 지원 창구에 상담한다. 이미 공개된 내용이 비밀이라고 가정하지 않는다.

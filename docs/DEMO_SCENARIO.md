# 틈길 결승 시연 시나리오

> 2026-10-29 · 구현된 로컬 MVP와 가상 자료를 사용하는 촬영안. 촬영 리허설과 녹화 시간 실측은 아직 하지 않았다. 기획 원문에 기록된 조건은 영상 7분 이내, 2026-11-13 제출이며 실제 촬영 전에 주최 측 최신 안내를 확인한다.

## 시연에서 보여 줄 한 가지

시민이 시장을 이용하다 불편을 선택적으로 알리고, 운영자가 확인한 뒤 관련 상인의 입장과 대안을 듣고, 시민에게 확인된 내용 또는 미해결 사유를 전하는 과정이다. 시장·점포·사람·의견은 가상이며 실제 협력이나 현장 개선 효과를 보여 주는 사례가 아니다.

S01–S13과 계정·서버 저장·역할별 처리는 구현됐다. 실제 지도 대신 점포 목록과 위치 설명을 사용하고, AI 생성 대신 원문을 직접 검토·정리해 제출한다. 사진은 선택 사항이며 작성자와 담당 운영자만 조회한다. 공식 신고 안내는 틈길 접수·처리 상태와 독립적이다. 실행 검증 결과와 한계는 [인수 기록](MVP_VERIFICATION.md)에 둔다.

## 실행 준비와 시작 상태

이 작업 공간의 앱은 PostgreSQL 17.11의 loopback 55432에 연결한다. 앱 DB와 테스트 DB는 별도이며 기존 PGlite 자료는 보존했다. 최초 설치·다른 환경의 DB 설정은 [개발 안내](DEVELOPMENT.md)를 따른다. 현재 작업 공간에서는 다음 명령을 사용한다.

```sh
npm run db:local:start
npm run demo:init
npm run dev
```

반복 촬영 전에 등록된 가상 자료를 시작 상태로 되돌릴 때는 다음 명령을 사용한다.

```sh
npm run demo:reset
```

`demo:init`은 가상 계정을 만들고 역할·담당 범위를 배정하며 준비된 사례를 추가한다. 기존 자료를 초기화하는 명령은 아니다. `demo:reset`은 로컬 레지스트리에 등록된 가상 계정의 장바구니·초안·첨부·의견 사례를 초기화한 뒤 기본 사례를 다시 만든다. 실제 시장 의견이나 다른 계정의 연결 기록이 있으면 거부하며 production에서 실행할 수 없다. 기본 PGlite로 실행하는 환경에서는 두 명령을 쓰기 전에 앱 서버를 종료해 같은 DB 파일의 동시 사용을 피한다.

계정과 비밀번호는 비공개 로컬 파일 `.harness/demo-accounts.json`에서 확인한다. PostgreSQL 설치·접속 정보는 `.harness/postgres-runtime.json`, 앱 연결 정보는 `.env.local`에 있다. 이 파일들, 세션·trace·로그는 커밋하거나 영상에 노출하지 않는다.

| 자료 | 실제 준비되는 상태 | 촬영 준비 |
| --- | --- | --- |
| 시장·점포 | `햇살시장 (가상)`의 `푸른채소 (가상)`가 대파·당근·감자를 평소 취급 | 실제 지도·주소·재고·가격으로 설명하지 않는다. 위치는 가상 A구역 설명을 사용 |
| 시민 계정 | 시민 가람 (가상) | 별도 브라우저 프로필 또는 독립된 세션으로 로그인 |
| 운영자 계정 | 운영자 온유 (가상), 햇살시장 담당 | 시민 세션과 다른 세션으로 로그인 |
| 상인 계정 | 상인 다온 (가상), 푸른채소 연결 | 운영자·시민과 다른 세션으로 로그인 |
| 장바구니 | 대파·두부·당근이 있는 목록 | 담기 장면을 보여 주려면 촬영 전에 UI에서 대파만 삭제. 빈 목록으로 초기화됐다고 설명하지 않음 |
| 준비 의견 | 접수 상태 한 건, 협의·상인 답변·시민용 게시·후속 계획이 있는 사례 한 건 | 실제 시연은 새 의견을 작성해 진행. 준비 의견은 녹화 실패 시 이미 저장된 예시로 구분 |

같은 브라우저의 일반 탭 세 개는 로그인 쿠키를 공유하므로 역할 분리에 쓰지 않는다. 독립된 세 계정의 창을 오가며 시연하고 역할 선택 UI나 요청 값 변경으로 권한을 우회하지 않는다. 계정 역할은 관리 CLI가 배정하며 실제 접근은 서버에서 검사한다. 이메일 소유 확인과 실제 점포 관계 검증을 완료했다는 의미는 아니다.

## 화면 순서와 발표 메모

시간은 연습 전 배분안이다. 같은 의견의 접수번호·전달번호를 따라 시민·운영자·상인의 서로 다른 화면을 보여 준다.

| 시간 | 화면과 행동 | 전달할 내용 |
| --- | --- | --- |
| 0:00–0:45 | 프로젝트 소개 | 보행·영업 공간의 불편을 확인과 협의로 연결하는 틈길 |
| 0:45–1:35 | S01–S04: 햇살시장 → 대파 취급 점포 검색 → 푸른채소 상세 → 장바구니 추가·체크 | 평소 취급 품목과 당일 재고·가격은 다름. 목록은 계정에 저장 |
| 1:35–2:35 | S05–S06: 시장과 위치 설명·상황 입력 → 내용 검토 → 직접 정리 | 알리기는 선택 사항. AI 생성 없이 원문을 확인하고 수정. 모르는 시점은 비우고 사진은 생략 가능 |
| 2:35–3:15 | S07: 틈길에 알리기 → 실제 접수번호·시각 확인 | 틈길 내부 접수이며 공식 신고는 별도 창구에서 이용 |
| 3:15–4:25 | S10–S13: 운영자 계정에서 확인 중으로 변경 → 관계 근거와 요약을 상인에게 전달 → 상인 계정에서 답변 | 원문·사진은 상인에게 전달하지 않음. 상인 답변은 운영자에게만 보임 |

| 5:20–6:15 | 검증할 과제 설명 | 실제 상인 참여, 운영 주체, 보관·삭제 정책, 현장 효과는 검증 전 |
| 6:15–6:45 | 마무리 | 일상 이용과 확인·협의를 연결하는 흐름 정리 |

계획상 6분 45초다. 실제 길이는 녹화로 확인하고, 시간이 부족하면 사진·추가 질문·후속 확인 결과 등 보조 장면을 줄인다. 실제 입력·저장·조회 장면은 남긴다.

## 본 시연에서 사용할 입력과 처리

입력마다 가상 시연 자료임을 표시한다. 사물과 특정 상인의 관계는 이용자 문장이나 점포 위치만으로 단정하지 않는다.

1. 시민 계정에서 대파를 찾아 담고 체크한다. 점포 목록·위치 설명과 재고·가격 미확인 표시를 보여 준다.
2. 햇살시장을 선택하고 위치에 `가상 A구역 입구 통로`, 상황에 `[가상 시연 자료] 통로에 놓인 상자 사이로 유모차가 지나가기 어려웠어요. 어느 점포의 물건인지는 모르겠어요.`를 적는다. 사진 없이 계속한다.
3. `내용 검토하기`로 이동해 원문과 직접 작성할 내용을 비교한다. 제목은 `A구역 통행 공간을 확인해 주세요`, 정리한 상황은 `[가상 시연 자료] 통행 공간이 좁게 느껴져 상황 확인을 요청해요. 물건의 소유 관계는 확인하지 못했어요.`로 입력하고 `틈길에 알리기`를 누른다.
4. 응답으로 받은 접수번호·시각을 확인한다. 공식 신고 창구 안내는 별도임을 설명하며 실제 공식 신고를 제출하지 않는다.
5. 운영자 세션에서 같은 접수번호를 찾고 먼저 `확인 중`으로 바꾼다. 상인 전달의 관계 근거에 `[가상 시연 설정] 운영자가 해당 구역과 점포의 관계를 확인한 상황을 가정한 자료`를 남긴다. 전달 요약은 `[가상 시연 자료] A구역 통행 공간에 관한 의견입니다. 점포와의 관련 여부, 가능한 대안을 알려 주세요.`로 작성하고 대상·요약 미리보기 후 전달한다.
6. 상인 세션에서 새 전달번호를 열고 입장에 `[가상 시연 답변] 어느 물건인지 더 확인이 필요해요.`를 입력한다. `지금 제안할 수 있는 대안이 없어요`를 선택하고 미리보기 후 답변한다. 답변만으로 처리 상태가 바뀌거나 시민에게 공개되지 않음을 보여 준다.
7. 운영자는 답변을 읽고 상태를 `확인 불가 / 대안 미확보`로 바꾸며 `[가상 시연 기록] 물건과 점포의 관련 여부가 확인되지 않았고 현재 가능한 대안을 확보하지 못했어요.`를 남긴다. 이어 `시민에게 게시`에서 같은 취지의 시민용 설명을 별도로 작성·확인·게시한다. 상태 변경 사유나 상인 답변 원문이 자동 공개된다고 설명하지 않는다.
8. 시간이 허용되면 후속 계획에 `위치와 통행 상황을 다시 확인할 예정`과 가상 담당자·예정 시각을 기록한다. 이를 수행 완료로 설명하지 않는다. 시민 세션의 `내 의견`에서 새로고침 후 같은 의견의 상태와 게시 내용을 확인한다.

추가 질문·시민 응답, 비공개 사진, 정정·재개, 실제 후속 결과 입력도 구현돼 있다. 본 촬영의 핵심 흐름에 모두 넣을 필요는 없으며 구현 범위·검사 결과는 [제품 명세](PRODUCT_SCREENS.md)와 [인수 기록](MVP_VERIFICATION.md)으로 설명한다. 외부 AI·지도·메일·공식 접수 연동은 작동하는 것처럼 시연하지 않는다.

## 촬영 리허설에서 확인할 것

아래는 촬영 담당자가 실제 리허설 뒤 표시할 항목이다. 자동 앱 검사 통과와 촬영·발표 완료를 구분하며 현재는 미실행이다.

- [ ] `demo:reset` 후 시작 상태를 확인하고 대파 삭제 등 촬영 준비를 거쳐 같은 흐름을 두 번 재현했다.
- [ ] 독립된 세 계정 세션과 새로고침 뒤 같은 의견·전달 ID를 확인했다.
- [ ] 가상 자료·시연 계정·직접 작성 표시가 영상에서 읽힌다.
- [ ] 사진을 추가하는 장면이 있다면 시민·담당 운영자에게만 보이고 상인 화면에서는 보이지 않는다.
- [ ] 공식 신고 안내가 내부 상태와 독립적임을 설명하고 긴급 위험 안내도 확인했다.
- [ ] 화면 글자·커서와 녹음된 설명이 잘 보이고 들리며 비밀번호·세션·연결 정보가 녹화되지 않았다.
- [ ] 녹화 시간을 실측하고 주최 측의 최신 제출 조건에 맞는지 확인했다.
- [ ] 저장 실패·세션 만료 시 복구하거나 준비된 저장 사례로 전환할 수 있으며, 대체 화면을 실시간 처리로 설명하지 않는다.

# MVP 구현과 인수 기록

2026-10-29 · 가상 자료를 사용하는 로컬 실행 검증. 승인된 [구현 범위](design/IMPLEMENTATION_SCOPE.md)를 기준으로 한다. 이 문서는 실제 실행 결과를 기록하며 제품 정책과 명세 ID를 다시 정의하지 않는다.

## 실행 환경

- Windows, Node.js 24.18.0, Next.js 16.4.3, Chromium Playwright.
- 기본 단위·통합 검사: 메모리 PGlite와 파일 저장 재시작 검사.
- 공유 DB 검사와 현재 앱 실행: 별도 PostgreSQL 17.11, loopback 55432. 테스트 DB와 앱 DB를 분리했다.
- 기존 로컬 변경·PGlite 파일·인증 설정을 보존했다. 커밋·푸시·외부 배포는 하지 않았다.

## 상태·저장·권한에서 확인한 경계

- 같은 요청 UUID의 재시도는 이미 저장된 결과를 반환한다. 응답 유실 검사는 서버 요청을 먼저 완료시킨 뒤 브라우저 응답만 끊는 방식으로 수행했다.
- 오래된 버전의 쓰기는 409다. 운영자는 입력을 유지한 채 최신 기록을 확인하고 다시 결정한다. 초안은 제출 후에도 버전 수열을 유지해 예전 탭이 새 초안을 덮어쓰지 못하게 한다.
- 장바구니의 정규화 이름 충돌, 사진 삭제와 접수의 경합, 권한 회수 중 상인 답변, 상태·이력 읽기 일관성을 실제 트랜잭션으로 검사했다.
- 사진은 파일명·MIME만 신뢰하지 않고 디코딩하며, 자원 상한과 메타데이터 제거를 적용한다. 업로드 재시도 UUID와 임시 첨부 조회로 응답 유실을 복구한다.
- 역할은 관리 명령으로만 부여한다. 시민 입력의 role은 무시한다. 운영자는 담당 시장, 상인은 연결 점포에 실제로 전달된 내용만 읽고 쓴다.
- UI에 렌더링된 계정과 실제 세션 계정이 다르면 쓰기를 거부한다. 세션을 읽기 전에 개인 폼을 보여 주었다가 초기화하는 경합도 수정했다.
- 브라우저 뒤로 가기의 자동 저장 실패는 계정별 탭 메모리에 보존한다. 새로고침·창 닫기 전에는 미저장 경고를 보여 준다. 원문을 localStorage나 sessionStorage에 저장하지 않는다. 탭을 강제로 종료했을 때 미저장 메모리까지 복원된다고 보장하지 않는다.

## 화면과 모션의 실제 관찰

공통 화면은 [구현된 화면 시스템](design/IMPLEMENTED_SYSTEM.md)에 색·서체·간격·분기점과 선택 근거를 기록했다. 시장 탐색은 검색·구분선 목록, 작성은 좁은 폼·원문 비교, 운영 접수함은 목록·미리보기, 운영 상세는 맥락·현재 업무·이력의 밀도를 다르게 구성했다.

axe는 WCAG A·AA 관련 자동 규칙을 검사했다. 이것을 전체 WCAG 적합성 판정으로 해석하지 않는다. 200% 검사는 요소의 계산된 글자 크기를 두 배로 바꾸어 줄바꿈과 가로 넘침을 확인한 것이며, 모든 브라우저의 확대 동작을 대신하지 않는다.

제품 13개 화면 × 320·390·768·1440px의 52개 조합과 가입·로그인 8개 조합에서 가로 넘침·axe 위반 0건이었다. 이는 공개·인증 20개, 시민 개인 화면 24개, 운영·상인 16개 검사 결과를 합친 수치다. 키보드 Tab·Shift+Tab 가두기, Esc 후 호출 요소 초점 복원, 읽기 실패 복구, 다른 계정 전환, 입력이 있는 상태의 로그아웃 취소를 확인했다. 운영 이력의 새 항목은 0ms에서 opacity .4·4px, 100ms 근처에서 opacity .86·.92px, 250ms에서 opacity 1·제자리였으며, 모션 줄이기에서는 처음부터 opacity 1·이동 없음이었다.

로컬 근거는 `.harness/product-qa/`, `.harness/operations-ui/actual-report.json`, `states-report.json`, `operator-journey.zip`, `operator-states.zip`, `.harness/postgres-final.txt`, `.harness/admin-cli-result.json`에 있다. 브라우저 기록에는 가상 계정의 세션·입력이 들어갈 수 있어 Git에서 제외했다. 저장된 ID는 검증 당시 ID이며, demo 초기화 뒤 새 ID가 생기는 것이 정상이다.

최종 브라우저 결과는 `.harness/playwright/runs/2026-10-29T04-08-36-133Z-24012/results/`에 있다. 시민 상태 테스트의 `citizen-evidence/results.json`과 24개 화면 캡처, 세 테스트의 `trace.zip`을 보존했다. `npm run test:e2e:report`로 HTML 보고서를 열 수 있다. 시연 반복 결과는 `.harness/demo-repeatability.json`, 기본 검증과 빌드는 `.harness/verify-final.txt`·`.harness/build-final.txt`에 있다.

### 발견한 오류와 수정

- 개인 폼이 초기 세션 조회보다 먼저 렌더링되며 입력을 잃는 경합을 수정했다. 개인 데이터 조회는 초기 세션 확인을 기다린다.
- 초안 debounce 안에 뒤로 가기를 하면 마지막 입력이 누락될 수 있었다. 이동 시 즉시 저장하고, 실패하면 계정별 탭 메모리에 남겨 복귀 때 복원한다. 실제 실패 회귀를 추가했다.
- Windows 작업 폴더 안에서 Playwright가 활성 trace 파일을 쓰다 EBUSY로 실패했다. 앱 assertion 완료와 별개로 runner는 실패한 것이며, 당시 불완전 trace를 최종 근거로 쓰지 않았다. 임시 폴더에서 같은 검사를 다시 수행해 통과했고, 완성 trace의 JSON 이벤트·DOM·화면 프레임과 복사 해시를 확인했다. 실행기에 이 기록·복사 방식을 반영했다. 파일을 잠근 프로세스는 특정하지 못했다.
- 시연 CLI를 연속 실행하면 인증 요청 제한에 도달했다. 인증을 먼저 확인한 뒤 초기화하고, 429는 서버의 재시도 시간을 존중해 최대 두 번 재시도한다. 인증 제한을 끄지 않았으며 실제 반복 실행을 통과했다.

## 검증하지 않는 범위

외부 AI·지도·메일·공식 신고 접수 연동, 실제 시민 자료 수집과 삭제 정책, 현장 개선 효과, 물리적인 모바일 기기·배포 환경·백업 복구는 이번 로컬 MVP 검증 범위 밖이다. 실제 AI가 없으므로 생성 응답 순서·AI 질문 해석에 해당하는 조건은 직접 작성 경로의 검증과 구분한다.

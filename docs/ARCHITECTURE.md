# 틈길 구현 구조와 기술 선택

현재 앱 코드는 없다. 이 문서는 **선택의 기준과 기능별 책임**을 정의하며, 특정 프레임워크나 저장소를 채택한 설계도가 아니다. 현재 선택과 보류 항목은 [결정 기록](PLANS.md)의 D1·D5·D7에서 확인한다.

## 기술을 고르기 전에 답할 것

- 같은 기기에서 가상 역할을 바꿔 시연하는가, 여러 기기가 같은 의견을 읽어야 하는가?
- 새로고침·브라우저 종료 후 유지할 자료와 초기화 범위는 무엇인가?
- 가상 자료로 동작을 검토하는 단계인가, 실제 원문·사진·계정을 취급하는 단계인가?

이 답이 저장·인증·연동 범위를 바꾼다. 발표 기한만을 이유로 제품 전체를 브라우저 저장 데모로 고정하지 않는다.

| 선택지 | 유지·공유 | 구현·검증 부담 | 맞는 상황 |
| --- | --- | --- | --- |
| 실행 중 메모리 | 같은 실행 안에서 공유, 새로고침 시 사라짐 | 초기화가 단순. 재진입 시 유실을 설명해야 함 | 일시적인 화면·상호작용 검토 |
| 브라우저 저장 | 같은 브라우저에서 유지 가능. 기기 간 자동 공유 없음 | 저장 실패·형식 변경·초기화 필요. 인증·접근 통제는 제공하지 않음 | 한 기기의 가상 시연 후보 |
| 서버 저장 | 구현한 정책에 따라 기기 간 유지·공유 | 인증·권한·연결 실패·보관·운영 필요 | 여러 기기 협업 또는 실제 운영 |

기존 제안은 한 기기 가상 시연에서 브라우저 저장을 검토하자는 것이다. 채택된 결정은 아니다.

## 책임과 데이터 흐름

```text
시민 화면 ─ 운영자 화면 ─ 상인 화면
             │ 사용자 행동
             ▼
점포 검색 · 장보기 · 의견 제출 · 전달/답변 · 결과 기록
             │ 권한/입력/업무 규칙
             ▼
선택한 저장 방식
의견 ID ─ 전달 ID ─ 답변·이력·후속 확인
```

그림의 기능은 책임 구분이며 각각 별도 서비스·폴더를 만들라는 뜻이 아니다. 작은 앱에서는 단순하게 구현하고, 실제 필요가 생길 때 나눈다.

| 책임 | 포함할 일 | 피할 결합 |
| --- | --- | --- |
| 화면 | 이름표, 입력, 현재 상태, 빈 결과·오류·다음 행동 | 화면마다 별도 의견 복사본을 저장하고 서로 다른 상태 유지 |
| 제품 동작 | 제품 명세의 인수 기준과 DATA_ACCESS의 행동 계약 적용 | 버튼 클릭만으로 권한·공개 범위까지 결정 |
| 저장 | 읽기·쓰기·실패 반환, 상태·이력 일관성, 초기화 | 저장 실패에도 성공 화면 전환 |
| 초안 생성 | 고정 지침과 원문 분리, 생성 방식 표시, 출력 검증 | 생성 응답을 제출·상태 변경으로 실행 |
| 외부 연동 | 실제 선택한 제공자만 연결, 실패·시간초과 처리 | 지도나 사진 존재만으로 재고·주소·내용 추정 |

실제 서버에서는 화면에서 전달받은 역할을 그대로 믿지 않고, 인증된 주체와 의견·점포·전달의 관계로 접근을 검사한다.

## 외부 기능을 추가할 때

| 기능 | 현재 상태 | 도입 시 필요한 판단 |
| --- | --- | --- |
| 지도 | 미선정 | 도식·목록으로 검토할지 실제 지도와 위치 권한이 필요한지 |
| AI | 프롬프트·출력 검증 도구만 있음 | 제공자·전송 범위·비용·고지·실패·실제 출력 평가 |
| 사진 | 선택 입력이라는 제품 구상 | 파일 종류·저장·메타데이터·접근·보관·삭제 |
| 인증 | 미구현 | 계정 확인·상인 관계·역할 부여와 회수 |
| 공식 신고 | 별도 창구 안내 | 실제 연동 없이 틈길 내부 상태와 연결하지 않음 |

구체적인 외부 제품을 선정할 때는 그 시점의 공식 문서·조건을 확인하고 D 항목에 근거를 남긴다.

## 코드와 검증을 연결할 때

제품 기준은 [PRODUCT_SCREENS](PRODUCT_SCREENS.md), 대상별 접근과 이력은 [DATA_ACCESS](DATA_ACCESS.md)를 읽는다. 앱 파일 경로는 실제 구조에서 찾고, 아직 존재하지 않는 `src/`나 API를 이미 구현된 것처럼 문서화하지 않는다.

현재 실행할 수 있는 것은 [개발 하네스](HARNESS.md)다. 앱을 구성하면 선택한 기술에 맞춰 타입 검사·린트·빌드와 A1–A7 동작 검증을 연결한다. 실제 인증·저장 도입 시 권한 거부, 저장 실패와 상태·이력 불일치를 추가 검증한다.

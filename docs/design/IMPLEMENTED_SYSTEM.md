# 틈길 화면 시스템 · 구현 기록

2026-10-29 · 사용자에게 승인받은 [디자인 방향](../DESIGN_DRAFT.md)을 바탕으로 MVP에 적용한 값과 확인 결과다. 제품 요구사항은 [화면 명세](../PRODUCT_SCREENS.md), 공개 범위는 [데이터 계약](../DATA_ACCESS.md)이 기준이다. 이 기록은 새 디자인 승인이나 OmD의 canonical 문서·승인 receipt를 대신하지 않는다.

값의 출처는 [공통 CSS](../../src/app/globals.css), [공통 컴포넌트](../../src/components/ui.tsx), [시민 화면 CSS](../../src/components/citizen/citizen.css), [운영·상인 화면 CSS](../../src/components/operations/operations.module.css)다. 아래 수치는 초안의 제안값과 달라진 부분을 포함한 현재 구현값이다.

## 색과 표면

따뜻한 바탕 위에 짙은 청록으로 주요 행동과 선택 상태를 표시한다. 시장·의견 목록은 구분선으로 이어 읽게 하고, 입력·검토·보조 맥락에 필요한 곳에 표면을 둔다. 홈의 시장 아이콘과 가상 자료 표시는 실제 점포 사진이나 현장 데이터로 오인하지 않도록 함께 노출한다.

| 역할 | CSS 토큰 | 구현값 |
| --- | --- | --- |
| 페이지 / 입력·본문 표면 / 보조 구획 | `--background` / `--surface` / `--surface-muted` | `#fffdf8` / `#fff` / `#f3f0e5` |
| 주요 행동 / 호버 / 선택 배경 | `--primary` / `--primary-hover` / `--primary-soft` | `#126b5b` / `#0d574a` / `#e5f2ed` |
| 본문 / 보조 문구 / 주요 버튼 글자 | `--text` / `--text-secondary` / `--on-primary` | `#1d302c` / `#52645e` / `#fff` |
| 구획선 / 입력 테두리 | `--border` / `--border-control` | `#dedfd6` / `#697b74` |
| 오류 / 오류 배경 / 확인 필요 | `--error` / `--error-soft` / `--attention` | `#a02f27` / `#fff0eb` / `#8a432a` |
| 모서리 | `--radius-sm` / `--radius-md` / `--radius-lg` | `8px` / `12px` / `16px` |
| 간격 | `--space-1` · `2` · `3` · `4` · `6` · `8` | `4` · `8` · `12` · `16` · `24` · `32px` |

입력 경계는 구획선보다 진하다. 공통 패널은 흰 배경·1px 구획선·12px 모서리, 운영 업무 구역은 16px 모서리를 쓴다. 일반 구역에는 그림자를 두지 않고 대화상자에만 깊이를 준다. 상태 배지는 이름과 점을 함께 표시하며, 색만으로 상태를 전달하지 않는다.

## 글자와 밀도

Pretendard Variable 1.3.9를 자체 호스팅하고 `font-display: swap`을 사용한다. 라이선스는 [OFL](../../public/fonts/OFL.txt)에 보관했다. 기본 글자는 16px, 본문 줄 높이는 1.6이다. 한글은 `keep-all`로 읽는 단위를 지키고 긴 ID·문자열에는 `overflow-wrap: anywhere`를 적용한다.

| 사용처 | 현재 크기·굵기·줄 높이 | 밀도를 정한 이유 |
| --- | --- | --- |
| 공통 화면 제목 | `clamp(28px, 3vw, 40px)` · 750 · 1.35 | 화면 목적을 먼저 읽게 함 |
| 홈 제목 | `clamp(36px, 4.8vw, 56px)` · 750 · 1.25 | 탐색 진입점에 넓은 여백을 배정 |
| 공통 구역 제목 / 시민 구역 제목 | 20px · 700 · 1.35 / 21px · 700 · 1.45 | 시민 화면은 읽는 간격을 조금 더 확보 |
| 운영 목록 제목 / 메타데이터 / 식별자 | `1.0625rem` · 650 · 1.6 / `.875rem` / `.75rem` | 제목·장소·시각·ID를 빠르게 구분 |
| 버튼·입력 | 16px / 24px, 버튼 굵기 650 | 기본 높이 48px, 줄바꿈은 고정 높이로 자르지 않음 |

공통 본문 최대 폭은 1200px, 시민 화면 내부는 1120px, 좁은 작성 화면과 상인 상세는 760px이다. 화면을 모두 같은 카드 격자로 맞추지 않고 아래와 같이 구성했다.

| 흐름 | 구현한 구성 |
| --- | --- |
| 시장 찾기·장보기 | 검색과 구분선 목록이 중심. 홈에는 310px 보조 구역, 장바구니에는 체크·이름·추가 조작을 분리한 행을 배치 |
| 의견 검토·접수 결과 | 원문과 수정할 내용을 나란히 비교하고 좁은 폭에서 세로 배치. 접수 결과는 실제 번호·시각과 다음 행동을 한 구역에 집중 |
| 운영자 접수함 | 목록 + 310px 선택 미리보기. 시장·상태·검색 조건을 목록 위에 두고 임의의 우선순위·해결률은 추가하지 않음 |
| 운영자 처리 상세 | 원문·질문·전달 맥락과 현재 업무·이력을 두 열로 배치. 업무 선택에 따라 입력을 보여 주고 전달·게시는 대상과 내용을 먼저 확인 |
| 상인 답변 | 받은 요약 → 입장과 대안 → 보낼 내용 확인 순서. 운영자에게만 전달되는 범위를 입력 가까이에 표시 |

## 입력, 초점, 피드백

입력 이름표는 입력 후에도 남는다. 오류는 입력 근처 설명과 `aria-invalid`를 사용하며, 공통 `Field`의 도움말·오류 ID 연결은 호출 화면이 맡는다. 처리 중 버튼은 비활성·`aria-busy`·문구로 진행 상태를 알린다. 빈 결과, 읽기 실패, 세션 만료, 저장 결과 미확인은 서로 다른 상태로 표시한다.

키보드 초점은 청록 2px 선과 바깥 간격 3px를 기본으로 쓴다. 장바구니 체크와 운영 업무 제목은 4px 간격이다. 본문 바로가기와 화면 이동 후 제목 초점이 있으며, 대화상자는 native `dialog`로 배경 조작을 막고 Tab 순환·Esc 닫기·호출 요소 초점 복원을 처리한다. 오류·성공 안내는 `alert` 또는 `status` 역할을 사용한다.

| 반응 | 현재 구현 |
| --- | --- |
| 버튼·체크·필터 | 150ms. 버튼 눌림은 최대 `scale(.98)`, 체크는 색·테두리·취소선으로 결과 표시 |
| 화면 셸 진입 | 200ms, 아래 6px에서 opacity와 함께 진입. 모든 경로 전환마다 재생되는 구조는 아님 |
| 보조 패널 열기·닫기 | 300ms·12px 진입, 200ms·8px 퇴장. 닫힌 뒤 호출 요소 초점 복원. 모션 줄이기에서는 즉시 닫음 |
| 장바구니 행 | [장바구니 코드](../../src/components/citizen/cart.tsx)의 Motion으로 위치·진입·퇴장을 200ms 연결 |
| 접수 확인 / 운영 이력 | 접수 확인 표식 200ms. 운영 이력은 저장된 새 항목만 아래 4px·200ms, 기존 이력은 재생하지 않음 |
| 모션 줄이기 | CSS 애니메이션·전환·부드러운 스크롤을 제거. 장바구니 Motion도 `useReducedMotion`으로 위치 애니메이션을 끔 |

모션은 저장 응답을 대신하지 않는다. 운영 화면은 충돌 시 입력을 보존하고 최신 내용 확인을 요청한다. 저장 응답이 끊기면 결과 미확인을 표시하고 같은 요청으로 재확인한다. 상인 답변 성공과 시민용 게시·상태 변경도 별도 행동으로 남겨 둔다.

## 참고 패턴을 적용한 부분

[화면별 참고 기록](SCREEN_REFERENCES.md)에 있는 TDS 입력·목록, Linear Triage, MOJ Timeline 캡처를 실제로 보고 사용했다. TDS에서는 지속되는 이름표와 행동 가까이 있는 피드백, Linear에서는 제목·시각·식별자가 구분된 접수함, MOJ에서는 사건·시각·내용이 이어지는 이력 구조를 가져왔다. GOV.UK 검토·확인 패턴은 원문 검토와 실제 접수 결과를 나누는 구성에 반영했다.

틈길에서는 청록·따뜻한 바탕, 한국어 긴 문장, 시장 이용 맥락에 맞게 크기와 간격을 다시 정했다. 특히 운영자 내부 기록·상인 답변·시민용 게시의 구분은 참고 화면의 시각 구조에 덧붙인 틈길의 업무 요구다. 공개 범위는 서버 응답부터 나누며 화면의 색이나 영역 구분에 맡기지 않는다.

## 확인한 결과와 남은 마감

직접 본 실제 캡처는 홈 1440px, 운영 접수함 1440px, 상인 답변 390px, 운영 상세 390px·글자 200% 등이다. 홈은 큰 제목과 검색, 구분선 목록의 위계가 유지됐다. 운영 접수함에서는 제목과 상태·시각을 나눠 읽을 수 있었고, 상인 모바일 화면에서는 전달 맥락과 답변 범위가 폼 앞뒤에 남았다.

로컬 Chromium·PostgreSQL·가상 계정으로 운영·상인 네 화면을 320·390·768·1440px에서 검사했다. 16개 조합에서 가로 넘침과 axe 위반은 검출되지 않았다. 대화상자의 Tab·Shift+Tab 순환, Esc 후 초점 복원, 390px에서 계산된 글자 크기를 두 배로 늘린 화면과 모션 줄이기도 확인했다. 새 이력은 일반 설정에서 4px·opacity .4로 시작해 제자리에 표시되고, 모션 줄이기에서는 처음부터 이동 없이 표시되는 프레임을 확인했다.

근거는 로컬 비커밋 자료인 `.harness/operations-ui/actual-report.json`, `states-report.json`, `S10-1440.png`, `S13-390.png`, `S11-390-text200-reduced.png`와 `.harness/product-qa/home-1440.png`에 있다. 자동 접근성 검사 결과를 전체 접근성 적합 판정으로 해석하지 않는다.

- 패널 퇴장은 공통 Modal의 Web Animations로 적용했다. 닫는 도중 재열기 시 이전 효과를 취소하고, 닫기 완료 후 초점을 복원한다. 실제 여정의 Esc·재열기와 시민 화면의 초점 회귀 검사에 포함했다.
- 세부 표면색·모서리·서체 크기에 화면별 값이 남아 있다. 공통 토큰으로 전부 정리된 상태는 아니며, 재사용할 표현이 늘면 의미에 맞게 승격해야 한다.
- 긴 운영 이력은 페이지가 길어진다. 모바일에서 업무 영역을 앞에 배치했지만 이력 페이지 분할·가상화는 없다. CSS 시각 순서와 DOM 읽기 순서의 차이는 보조공학 수동 검토가 남아 있다.
- 이 기록의 검증 범위에는 실제 모바일 기기의 한글 키보드·스크린리더·브라우저별 확대, 현장 LCP·INP 분포, 실제 시장 이용자 사용성 검사가 포함되지 않는다. 로컬 캡처와 글자 크기 변경으로 이를 대체하지 않는다.

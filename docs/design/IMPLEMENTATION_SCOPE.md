# Astra 구현 범위 · 승인된 MVP

2026-10-29 사용자가 이 문서의 권고안 전체를 이번 MVP 기준으로 채택했다. 정책 기준은 [PLANS](../PLANS.md), [데이터·권한](../DATA_ACCESS.md), [장보기](../screens/SHOPPING.md)로 옮겼다. 아래는 실행 범위의 요약이며 구현 완료 기록이 아니다.

## 이번 구현의 결과

기존 서비스 기반을 이어서 시민·운영자·상인이 별도 계정·브라우저에서 같은 의견을 처리하는 서버 저장 MVP를 만든다. S01–S13과 가입·로그인을 연결한다. 화면·오류·빈 상태·모션·접근성·PostgreSQL 검증·재현 가능한 시연을 포함한다. 첫 화면이나 API만으로 완료하지 않는다.

검증은 가상 시장·점포·계정·의견을 사용한다. 실제 저장·세션·권한으로 동작하고 가상 자료임을 표시한다. 외부 시장 협력·현장 개선 성과는 만들어 넣지 않는다.

## 외부 연동의 완료 기준

의견 정리 AI는 기존 고정 지침·스키마·평가를 유지한다. 제공자와 키가 실제로 준비돼 있으면 서버에서 연결하고 출력 검증·시간초과·실패를 확인한다. 키가 없으면 직접 작성 경로로 전체 접수·처리 흐름을 검증하고 실제 AI 연동은 미검증으로 남긴다. 개발용 템플릿을 실제 AI로 표시하지 않는다.

실제 지도는 선택한 제공자의 조건·키가 있어야 연결한다. 준비되지 않았을 때도 점포 목록과 위치 설명으로 전체 흐름을 사용할 수 있게 하고 가상 도식을 실제 지도처럼 표시하지 않는다.


## 별도 결정·실행이 필요한 것

실제 지도·AI·메일·호스팅 제공자, 실제 시민 자료의 보관 기간·삭제·동의와 production 수집·배포는 이번 승인에 포함되지 않는다. 외부 연동이 없더라도 핵심 흐름을 끝내고, 실제 연동이 필요한 부분만 제한과 필요한 설정을 기록한다.

실행 요청은 [Astra 구현 프롬프트](../prompts/ASTRA_BUILD.md)에 있다. 이 준비 작업에서는 앱 화면을 구현하지 않는다.

검토일: 2026-10-29. 이 문서는 초기 지침 검토의 기록입니다. 이후의 문서 책임 재구성은 [개발 계획](PLANS.md)에 기록하며, 현재 기준 자료와 스킬은 [AGENTS](../AGENTS.md)에서 찾습니다. 아래의 당시 반영 위치를 현재의 문서 소유 관계로 해석하지 않습니다.

## 문서 체계 재검토 · 2026-10-29

사용자가 요청한 것은 실제 작업을 바꾸는 MD다. 기존에는 문서 제목과 체크리스트를 채웠지만, 판단할 정보의 소유 위치와 작업·검증의 연결이 약했다. 개편에서는 다음을 고쳤다.

| 문제 | 수정한 구조 | 수정에 따른 실제 차이 |
| --- | --- | --- |
| 제품 기준·상태가 여러 문서에 중복 | 제품 R1–R8과 화면은 PRODUCT_SCREENS, 데이터·권한·상태는 DATA_ACCESS | 문구·디자인·스킬이 원본을 참조하며 상태 정의를 복사하지 않음 |
| 참고 문서와 실행 지침의 구별 부족 | AGENTS는 작업별 경로, SKILL은 특정 작업 절차, 문서는 계약, 하네스는 검사 | 의견 흐름·앱 AI 평가 요청에서 읽을 자료와 완료 조건을 찾을 수 있음 |
| 제품 개발을 발표 데모로 축소 | 제품 명세와 별도 DEMO_SCENARIO | 발표용 가상 장면을 전체 제품 요구로 승격하지 않음 |
| 미정 항목 나열 후 끝남 | PLANS D1–D7에 결정 시점·의존 작업·영향 | D3 상태·이벤트, D4 공개 범위처럼 실제 구현 전에 풀 문제가 드러남 |
| 자동 검사에서 자체 스킬도 제외 | teumgil-*만 문서 검사에 명시적으로 포함 | 외부 스킬은 건드리지 않으면서 자체 스킬의 잘못된 참조를 검사 |

### 요청 사례로 자체 검토한 경계

[8개 사례](../evals/skills/cases.json)는 기대 동작을 기록한 자료다. 다음 표는 작성자가 설명·기준 문서를 대조한 **자체 검토**이며, 모델을 별도로 실행해 자동 선택이나 성능을 측정한 결과가 아니다.

| 사례 | 대조한 기준 | 자체 검토에서 확인할 판단 |
| --- | --- | --- |
| flow-share | 데이터 행동 계약·D4 | 답변 저장과 시민 공개를 나누고 공개 결정을 자동 채우지 않음 |
| flow-state | 상태표·D3 | 공식 안내와 협의가 동시에 일어날 수 있음을 드러냄 |
| eval-change | 앱 프롬프트·unknown-owner 사례 | 소유자 미확인 사례를 재사용하며 불필요하게 프롬프트·사례를 늘리지 않음 |
| eval-incomplete | 평가 CLI | 실제 명령으로 12/13 사례 입력을 거부하는 것 확인. 아래 실행 근거와 구분 |
| negative-style | 스킬 설명·디자인 기준 | 동작·의미를 유지하는 색상·모서리 변경은 개발 흐름·AI 평가 스킬의 대상 아님 |
| negative-user-text | 스킬 설명·앱 AI 역할 | 이용자 입력 정리와 개발용 프롬프트 변경을 구별 |
| negative-demo | 스킬 설명·발표 문서 역할 | 발표 장면 수정이 제품 구현을 시작하는 근거가 되지 않음 |
| mixed-contract | 제품 폼·앱 AI 안내 | missing_fields와 필수 입력, 생성 상태와 내부 처리 상태를 구별 |

### 실행한 것과 남은 검증

- 두 스킬을 skill-creator의 quick_validate로 검사했다. 기본 Python에 PyYAML이 없어 로컬 .harness/skill-validator-deps에만 준비한 뒤 실행했다. 프로젝트 런타임 의존성을 추가하지 않았다.
- 프로젝트 문서와 스킬 링크 검사, 자체 스킬 참조 오류를 잡고 vendor 문서는 제외하는 회귀 검사를 실행했다.
- 가상 기준 출력을 수동 자료로 표시하고 1개 사례를 제거한 파일을 평가 CLI에 전달했다. 종료 코드 1, expected 13 / received 12, outcome rejected를 확인했다. 실패 사례를 정상 모델 평가로 보고하지 않았다.
- 독립 에이전트의 스킬 선택·동작, 실제 앱·모델·권한·현장 효과는 미검증이다. 자체 워크스루나 YAML 통과로 이를 대체하지 않는다.

기본 검증의 최종 실행 결과는 [PLANS](PLANS.md)에 남긴다.

## 이번 작업의 범위

최종 개발 지침은 저장소 루트의 **AGENTS.md 하나**로 관리합니다. 별도 `agent.md`나 복제된 최종본을 만들지 않았습니다. 앱 AI 프롬프트는 별도의 적용 대상이며 계속 버전 관리합니다.

원본 기획의 제안을 실제 협력·운영 성과로 확정하거나 프런트엔드·백엔드·AI 제공자를 선정하지 않았습니다. 앱 구현과 외부 게시·배포는 이번 문서 작업에 포함하지 않았습니다.

출력 스키마나 검증 코드의 동작을 바꾸지 않고 프롬프트의 표현을 기존 규칙에 맞췄습니다. 프롬프트 해시가 바뀌므로 이전 버전으로 생성한 결과는 현재 평가에 재사용할 수 없습니다. 실제 모델 평가를 진행할 때 새 프롬프트로 출력을 수집해야 합니다.

## 검증과 남은 사항

문서 링크·JSON 예시, 기존 검증 도구 테스트와 기준 출력 검사를 다시 실행해 통과했습니다. 실제 명령과 결과는 [개발 계획](PLANS.md)의 최근 검증 기록에 남겼습니다.

현재 검증은 실제 모델이 새 지침을 잘 따르는지, 앱의 권한·저장 기능이 작동하는지, 현장에서 효과가 있는지를 증명하지 않습니다. 제품 구현·모델 연결·GitHub 업로드 단계에서 각각 확인합니다.

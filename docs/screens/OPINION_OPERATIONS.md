# 의견 조회·확인·협의 상세 명세 · S08–S13

[화면 공통 기준](COMMON.md)과 [데이터 계약](../DATA_ACCESS.md)을 적용한다. 아래 화면은 **같은 의견을 역할별 허용 범위로 조회하는 설계**다. 시민용 결과, 운영자 내부 기록, 상인 전달·답변을 하나의 공개 본문으로 취급하지 않는다.

D3(상태·이벤트)와 D4(전달·공개)가 미결정인 부분은 조건부로 명시한다. 시안을 작성할 수 있어도 정책을 확정한 실제 운영 화면으로 설명하지 않는다.

## S08 마이·내 의견 목록

| 항목 | 명세 |
| --- | --- |
| 목적 | 본인이 남긴 의견과 공개된 진행 정보를 찾는다 |
| 진입 | 마이 탭 |
| 읽는 자료 | 본인/데모 주체, 그 주체의 의견 ID·제목·시장·접수 시각·시민용 현재 상태 |
| 주요 행동 | 의견 선택 → S09 |
| 결정 필요 | D7 본인 식별·접근, D4 공개 필드 |

### 구성·행동

- 현재 주체와 데모 여부를 표시한다. 실제 로그인 구현 없이 개인 계정 인증이 된 것처럼 보이지 않게 한다.
- 의견 목록은 자신에게 허용된 건만 읽는다. 최신 접수 시각 순 정렬을 초기 제안으로 둔다.
- 각 항목은 제목, 위치 또는 시장 요약, 접수 시각, 시민용 상태를 표시한다. 원문·사진·내부 메모를 목록에 자동 노출하지 않는다.
- 항목 선택 시 의견 ID로 S09를 연다. 돌아오면 목록 위치·필터를 유지하는 안이다.
- 냉장고·저장 점포·알림은 별도 범위다. 빈 영역을 채우기 위해 구현된 메뉴처럼 만들지 않는다.

정상적으로 의견이 없으면 작성 경로를 안내한다. 목록 읽기 실패·인증 필요·접근 불가는 다른 상태다. 인증·서버가 없는 가상 시연은 그 한계를 표시한다.

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S08-T1 | 주체 A·B의 의견이 있을 때 A로 조회 | A에게 허용된 의견만 표시 |
| S08-T2 | 의견 없음과 읽기 실패를 각각 확인 | 서로 다른 안내와 다음 행동 |
| S08-T3 | 항목 선택 후 복귀 | 같은 의견 ID·목록 맥락 유지 |

## S09 시민 의견 상세

| 항목 | 명세 |
| --- | --- |
| 목적 | 본인의 제출 내용, 공개된 처리 결과와 추가 질문을 확인한다 |
| 진입 | S08 항목, S07의 내 의견 보기 |
| 필수 맥락 | 의견 ID·작성 주체 |
| 읽는 자료 | 본인 제출 내용·첨부, 시민용 상태·이력·추가 질문·후속 확인 |
| 쓰기 | 열린 추가 질문에 대한 이용자 응답 제안. 원문 정정·삭제는 정책 미정 |
| 결정 필요 | D3 응답 후 상태 처리, D4 공개 범위, D5 보관·정정·삭제, D7 권한 |

### 표시 구역

| 구역 | 표시할 것 | 제외·조건 |
| --- | --- | --- |
| 현재 요약 | 의견 제목·시장·위치, 내부 상태 | 실제 공식 접수·담당 기관을 임의 표시하지 않음 |
| 내가 제출한 내용 | 원문·검토 내용·발견 시점·접수 시각 구분, 저장된 첨부 | 발견 시점이 없으면 미입력. 첨부 접근 확인 |
| 확인 과정 | 시민에게 공개하기로 한 기록의 행동·시각·내용 | 내부 메모·상인 답변 전체는 D4 없이 자동 노출하지 않음 |
| 추가 질문 | 실제로 요청받은 질문과 응답 상태 | 질문이 없으면 입력창을 상시 의무 항목으로 두지 않음 |
| 결과·후속 확인 | 확인된 조치 또는 미해결 사유, 담당 주체·시각, 공개 가능한 후속 계획·결과 | 예정과 실제 수행, 조치 확인과 완전 해결 구분 |
| 별도 경로 | 공식 신고 창구 이용, 긴급 위험 안내 | 내부 상태와 독립적 |

### 추가 정보 응답 제안

질문이 열려 있을 때 질문 내용·작성한 응답을 확인하고 저장한다. 질문/의견 ID에 연결된 새 응답으로 남기며 기존 원문을 덮어쓰지 않는다. 저장 실패 시 입력을 유지한다. 답변 저장만으로 어떤 처리 상태로 전환할지는 D3에서 결정한다.

화면은 공개용 기록을 받도록 설계한다. 전체 내부 기록을 내려받아 화면에서 숨기는 방식으로 공개 범위를 대신하지 않는다.

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S09-T1 | 내부 메모·상인 답변과 시민용 결과가 함께 존재 | 시민에게 허용된 내용만 조회·표시 |
| S09-T2 | 후속 확인 예정만 기록된 상태 조회 | 완료로 표시하지 않음 |
| S09-T3 | 추가 질문 응답 저장 실패 | 작성값 유지, 원문·상태에 거짓 변경 없음 |
| S09-T4 | 대기 상태에서 공식 경로 선택 | 내부 처리·운영자 확인을 선행조건으로 두지 않음 |

## S10 운영자 의견 목록

| 항목 | 명세 |
| --- | --- |
| 목적 | 담당 범위의 접수·확인·협의 대상 의견을 찾는다 |
| 진입 | 실제 운영자 진입 또는 표시된 데모 역할 전환 |
| 읽는 자료 | 허용된 의견 목록, 시장·의견 ID·접수 시각·현재 상태 |
| 주요 행동 | 조건 검색·선택 → S11 |
| 쓰기 | 조회 조건만 변경. 목록 조회로 상태를 바꾸지 않음 |

### 목록과 필터

- 최신 접수 시각 순을 초기 정렬 제안으로 둔다. 실제 우선순위 정책이 없으면 자동 위험도·긴급 등급·처리 기한을 만들지 않는다.
- 시장·현재 상태로 좁혀 보고 의견 ID로 찾는 안을 사용한다. 상태 필터는 D3에서 승인한 상태 구조와 맞춘다.
- 목록에 필요한 위치 요약과 제목을 표시한다. 원문·사진은 목록에서 한꺼번에 공개하지 않는다.
- 건수는 현재 권한과 필터의 실제 조회 결과일 때만 표시한다. 전체 건수와 현재 페이지 건수를 혼동하지 않는다.
- 여러 의견의 일괄 상태 변경·자동 배정·공무원 전용 처리는 이 범위에 추가하지 않는다.

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S10-T1 | 시장·상태 조건 변경 | 적용 조건과 결과 일치, 다른 요청의 늦은 응답에 덮이지 않음 |
| S10-T2 | 목록에서 같은 의견을 여러 번 조회 | 접수·확인 이력이 조회만으로 증가하지 않음 |
| S10-T3 | 권한 없는 운영 범위로 진입 | 의견·첨부를 노출하지 않고 접근 제어 |

## S11 운영자 의견 상세·처리

| 항목 | 명세 |
| --- | --- |
| 목적 | 원문·위치 확인부터 추가 질문, 상인 협의와 결과 기록까지 연결한다 |
| 진입 | S10의 의견 선택 |
| 읽는 자료 | 담당 의견, 원문·검토 내용, 허용된 사진, 상태·내부 이력·전달·답변·후속 확인 |
| 쓰기 | 확인 기록, 질문, 상인 전달, 승인된 상태·결과, 후속 확인 |
| 주요 이동 | 목록 복귀, 관련 상인 전달·답변 영역 |
| 결정 필요 | D3 전이·정정, D4 전달·공개, D5 첨부·보관, D7 담당 권한 |

### 정보 구역

1. **대상·상태:** 의견 ID·시장·접수 시각, 현재 상태와 담당 범위.
2. **이용자 입력:** 위치·상황 원문·발견 시점, 검토한 제출 내용·첨부. 원문과 운영자 확인 내용을 구분한다.
3. **확인·추가 질문:** 무엇을 확인했는지와 아직 필요한 정보.
4. **상인 전달·답변:** 전달 대상·근거·실제 전달 내용, 전달별 답변.
5. **결과·후속 확인:** 확인된 조치 또는 미해결 사유, 계획과 수행.
6. **변경 이력:** 행동·담당 주체·시각·사유. 실제 기록이 없으면 만들어 채우지 않는다.

### S11-O1 확인 기록·추가 질문

| 입력·행동 | 조건 | 저장·표시 |
| --- | --- | --- |
| 확인 내용 | 근거 있는 내용과 미확인을 구분 | 담당 주체·시각과 기록. 이용자 원문을 수정하지 않음 |
| 추가 질문 내용 | 물어볼 내용이 비어 있지 않음 | 의견에 연결된 질문. S09에 공개할 범위는 D4 |
| 확인 시작·상태 변경 | 승인된 상태 전제와 권한 확인 | 상태와 이력을 함께 반영. 단순 상세 조회로 시작 처리하지 않음 |

질문을 저장한 것과 외부 알림 발송은 다르다. 실제 알림 연동이 없으면 알림이 전송됐다고 표시하지 않는다.

### S11-O2 상인 전달

| 필드 | 필수 제안 | 검증 |
| --- | --- | --- |
| 대상 점포·상인 | 필요 | 현재 의견과 관련성을 확인한 대상인지 확인. 위치 근접으로 자동 결정하지 않음 |
| 관련성 확인 근거 | 필요 | 확인한 근거를 기록. 추정이면 확인 필요로 남김 |
| 전달할 내용 | 필요 | 해당 상인에게 필요한 상황·질문만. 이용자 원문·내부 메모 자동 복사 금지 |
| 선택 첨부 | 선택·정책 의존 | D4·D5에 따라 필요한 범위만. 전체 파일 접근을 기본 부여하지 않음 |

저장 전 대상과 전달될 내용의 미리보기를 제공하는 안이다. 성공 후 전달 ID와 시각을 보여 주고 해당 상인의 S12에 연결한다. 실패·결과 미확인은 C3을 따른다. 다른 상인으로 다시 전달할 때는 대상을 바꾼 새 전달로 구분하며 이전 기록을 덮어쓰지 않는다. 실제 전달·재전달 정책은 D4에서 확정한다.

### S11-O3 결과·상태·후속 확인

| 필드 | 조건 | 구분 |
| --- | --- | --- |
| 결과 구분 | 승인된 D3 정책 사용 | 확인된 조치 / 확인 불가·대안 미확보 등의 의미를 데이터 계약과 맞춤 |
| 확인 내용 또는 미해결 사유 | 결과를 뒷받침하는 내용 필요 | 예정 조치만으로 조치 확인을 저장하지 않음 |
| 실제 확인 시각 | 확인된 경우 실제로 아는 시각 | 기록 생성 시각을 현장 확인 시각으로 대체하지 않음 |
| 변경 사유·담당 주체 | 상태 변경 시 기록 | 인증 주체와 표시 담당자 구분을 D7에서 결정 |
| 후속 확인 계획 | 계획을 등록할 때 담당 주체·예정 시점 | 결과와 별도. 수행 시 실제 확인 시각·내용 기록 |
| 시민용 공개 내용 | D4에 따른 범위 | 내부 기록·상인 답변을 일괄 공개하지 않음 |

상태와 이력이 함께 저장된 뒤 최신 내용을 다시 보여 준다. 다른 운영자가 먼저 수정했다면 최신 기록을 확인하고 덮어쓰기 여부를 판단하도록 한다. 충돌 감지·정합성 방법은 D1·D3에서 정한다. 임의의 되돌리기·재개·이력 삭제 버튼은 정책 없이 추가하지 않는다.

## S12 상인 전달 목록

| 항목 | 명세 |
| --- | --- |
| 목적 | 본인에게 전달된 의견을 찾아 답변한다 |
| 진입 | 실제 상인 진입 또는 표시된 데모 역할 전환 |
| 읽는 자료 | 본인 점포·상인 관계, 해당 대상의 전달 ID·전달 시각·허용된 요약·답변 여부 |
| 주요 행동 | 전달 선택 → S13 |
| 쓰기 | 없음. 목록 조회만으로 의견 상태를 바꾸지 않음 |

전체 시장의 모든 시민 의견이 아니라 **본인에게 전달된 기록**을 보여 준다. 제목·전달 시각·필요한 위치 설명과 답변 여부를 초기 표시안으로 둔다. 답변 여부는 실제 답변 저장 여부이며 내부 처리 완료와 다르다.

| --- | --- | --- |
| S12-T1 | 다른 상인에게만 전달된 기록 존재 | 본인 목록에 노출하지 않음 |
| S12-T2 | 전달된 건 없음 | 정상 빈 목록. 전체 의견을 대체 자료로 보여 주지 않음 |
| S12-T3 | 전달 ID 선택 | 같은 대상 관계의 S13 진입 |

## S13 상인 전달 상세·답변

| 항목 | 명세 |
| --- | --- |
| 목적 | 운영자가 전달한 내용에 입장·가능한 대안을 남긴다 |
| 진입 | S12의 본인 전달 선택 |
| 필수 맥락 | 전달 ID, 연결 의견 ID, 대상 상인 |
| 읽는 자료 | 허용된 전달 내용·선택 첨부·운영자 질문, 본인의 답변 기록 |
| 쓰기 | 해당 전달에 연결된 답변 |
| 결정 필요 | D4 전달 내용·답변 공개·수정·재답변, D7 상인 확인 |

### 표시·입력

| 영역·필드 | 조건과 동작 |
| --- | --- |
| 전달 맥락 | 시장·대상 점포·전달 시각, 의견 자체와 전달의 관계 |
| 전달 본문 | 실제 전달된 내용만 표시. 시민 원문·내부 메모는 기본 열람하지 않음 |
| 관련성 정정 | 본인 물건·점포와 무관하다는 입장을 적을 수 있음. 소유 확인을 강요하지 않음 |
| 입장 | 비어 있지 않은 답변 내용 제안. 실제 상황을 상인이 설명 |
| 가능한 대안 | 선택 내용. 대안 없음·답변하기 어려움도 표현할 수 있게 함 |
| 답변 저장 | 대상 관계·입력 확인 후 전달 ID에 연결. 상태 변경·시민 공개는 별도 정책 |

저장 전 내용을 확인할 수 있고, 실패하면 입력을 유지한다. 저장 성공 후 본인 답변·시각을 표시하고 운영자의 같은 전달에 연결한다. 이미 답변한 건의 수정·재답변·삭제는 D4에서 정하기 전 버튼을 약속하지 않는다.

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S13-T1 | 무관한 전달 ID로 조회·저장 요청 | 본문·첨부 접근과 답변 저장 거부 |
| S13-T2 | 입장과 대안 없음 저장 | 정상 협의 기록으로 연결. 자동 해결·조치 완료 없음 |
| S13-T3 | 답변 저장 성공 후 역할 전환 | 운영자가 같은 의견·전달 ID의 답변을 확인 |
| S13-T4 | 저장 실패·결과 미확인 | 입력 유지, 중복 답변이나 거짓 성공 처리 없음 |
| S13-T5 | 상인이 답변 저장 | D4 없이 시민에게 답변 전체가 자동 노출되지 않음 |

## 역할 간 연결 검증

하나의 가상 의견으로 S05 → S06 → S07 → S10·S11 → S12·S13 → S09를 확인한다.

- 의견 ID는 같고, 상인에게 전달할 때 전달 ID가 별도로 연결되는가?
- 시민이 보는 내용, 상인이 받은 내용, 운영자의 내부 기록이 각 계약과 일치하는가?
- 각 저장 뒤 실제로 읽은 결과가 반영되는가? 화면에 미리 넣은 별도 가상 복사본으로 연결을 흉내 내지 않는가?
- 대안 없음·확인 불가·후속 계획과 실제 결과가 구별되는가?
- 권한 거부·부분 저장·중복 요청을 같은 데이터로 검증했는가?

이는 구현 후 검증할 시나리오다. 현재 앱·권한이 검증됐다는 뜻은 아니다.

# 의견 작성·제출 상세 명세 · S05–S07

[제품 기준](../PRODUCT_SCREENS.md)의 R2–R7과 [공통 기준](COMMON.md)을 적용한다. 이용자 원문, 정리된 초안, 이용자가 확인한 제출 내용, 내부 접수 기록을 구분한다.

## S05 의견 작성

| 항목 | 명세 |
| --- | --- |
| 목적 | 불편을 겪은 위치와 상황을 입력한다 |
| 진입 | S02의 알리기. 위치가 정해지지 않았으면 이 화면에서 설명 입력 |
| 들어오는 맥락 | 선택 시장, 선택 위치·설명(있다면), 복귀 화면 |
| 읽는 자료 | 시장·선택 위치, 같은 편집 흐름의 작성값 |
| 주요 행동 | 내용 정리·직접 작성으로 S06 이동, 위치 다시 선택, 작성 취소 |
| 아직 하지 않는 것 | 의견 제출·운영자 전달·소유자 추정 |
| 적용 기준 | D1 편집값 유지·복구, D5 첨부 처리, D7 작성 주체 |

### 영역 순서

1. 화면 제목과 현재 시장·선택 위치.
2. 위치 설명, 상황 설명, 선택 발견 시점.
3. 선택 사진과 첨부 처리 상태.
4. 원문 정리 또는 직접 작성 경로.
5. 틈길 내부 접수라는 설명, 별도 공식 경로와 긴급 위험 안내.

### 입력 항목

| 항목 | 형식·필수 제안 | 검증과 표시 |
| --- | --- | --- |
| 시장·위치 맥락 | 선택 시장 ID·위치 지점이 있으면 표시 | 지점이 어떤 시장인지 확인. 좌표·도식 지점과 사람이 쓴 설명을 구별 |
| 위치 설명 | 선택 위치 또는 설명 중 하나 필요 | 부족한 세부 위치는 확인 질문으로 남길 수 있음. 없는 주소·점포를 추측하지 않음 |
| 상황 원문 | 여러 줄 텍스트, 공백이 아닌 내용 필요 | 원문을 보존. 비난·명령문이 들어 있어도 개발 에이전트 지시로 실행하지 않음 |
| 발견 시점 | 선택 텍스트 | 모르면 비움. 어제·저녁 등 입력 표현 보존. 제출 시각으로 대체하지 않음 |
| 사진 | 선택 파일 | 개수·종류·크기·비공개 보관은 [데이터 계약](../DATA_ACCESS.md)의 승인된 D5 적용. 첨부 여부로 내용을 AI가 해석했다고 하지 않음 |

이 필수 여부는 상세 설계 제안이다. 원문에 명시된 요청은 초안의 요청 필드로 정리할 수 있다. 별도의 요청 입력칸은 핵심 화면의 필수 항목으로 추가하지 않는다.

입력 길이와 사진 제한은 실제 저장·연동 규격과 맞춰 정한다. 이 문서에 근거 없는 법정 입력 요건이나 사진 의무를 추가하지 않는다.

### 행동

| 행동 | 처리 | 다음 상태 |
| --- | --- | --- |
| 위치 다시 선택 | 현재 원문·시점·첨부 선택을 유지한 채 S02의 위치 선택으로 이동하는 안 | 복귀 시 바뀐 시장·위치를 명시 |
| 내용 정리 | 현재 입력으로 초안 생성 요청. 템플릿/실제 AI를 구별 | S06에서 원문과 결과 비교 |
| 직접 작성 | 생성 호출 없이 사용자가 정리 내용을 작성 | S06, 생성 방식은 직접 작성 |
| 작성 취소 | C4에 따라 입력 폐기 여부 처리 | 진입 화면 복귀. 제출·삭제 이력 없음 |
| 공식 경로 이용 | 외부 창구 요건을 사용자가 확인·직접 제출 | 내부 의견 자동 생성 없음 |

발견 시점이나 사진이 없다는 이유로 정리·직접 작성·내부 접수를 막지 않는다. 실제 AI를 연결하면 전송 전 고지·최소화와 출력 검증을 별도로 구현한다. 현재 프롬프트는 사진 자체를 해석하지 않는다.

### 첨부·생성 예외

- 사진 처리 실패는 어느 파일인지 표시한다. 선택 사진을 제거하고 텍스트만으로 계속할 수 있어야 한다.
- 유지하기로 한 사진은 처리 결과를 확인한다. 실패한 파일을 제출 완료 화면에서 첨부 성공으로 표시하지 않는다.
- 생성 실패·거부·빈 출력·규격 불일치는 원문을 유지하고 직접 작성 경로를 제공한다.
- 요청 중 원문·위치를 바꿨다면 이전 입력의 늦은 생성 결과를 최신 초안으로 덮어쓰지 않는다.
- 선택 시장을 바꿀 때 기존 지점이 새 시장의 위치인 것처럼 남지 않게 한다.

### 인수 조건

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S05-T1 | 위치·상황 입력, 시점·사진 비움 | 선택 항목 강제 없음. S06으로 이동 가능 |
| S05-T2 | 상황 공백 또는 위치 정보 모두 없음 | 해당 필드 오류와 수정 경로. 다른 입력 유지 |
| S05-T3 | 선택 사진 실패 후 제거 | 텍스트만으로 계속 가능. 실패 첨부를 성공 표시하지 않음 |
| S05-T4 | 생성 중 원문 변경 후 이전 응답 도착 | 새 원문 유지. 이전 결과를 무조건 채택하지 않음 |

## S06 원문·초안 검토와 제출

| 항목 | 명세 |
| --- | --- |
| 목적 | 이용자가 실제 전달할 내용을 확인·수정하고 제출 여부를 정한다 |
| 진입 | S05의 정리 또는 직접 작성, 같은 편집 흐름의 재진입 |
| 읽는 자료 | 원문·입력 위치·시점, 생성 방식과 검증된 결과, 이용자 수정값, 첨부 상태 |
| 쓰는 자료 | 수정된 제출 내용. 이용자 제출 후에만 내부 의견·접수 이력 |
| 주요 행동 | 수정, 원문 다시 편집, 필요 시 다시 정리, 틈길에 알리기 |
| 적용 기준 | D1 저장·재시도, D5 첨부·보관. AI의 출력 구조는 기존 스키마 유지 |

### 검토 영역

| 영역 | 정보·조작 | 구분할 것 |
| --- | --- | --- |
| 원문 | S05에 쓴 상황·위치·발견 시점 확인 | 원문을 AI 결과로 덮어쓰지 않음 |
| 정리된 내용 | 제목·위치·시점·상황·명시된 요청의 확인·수정 | 원문에 없는 요청·주소·날짜를 자동 추가하지 않음 |
| 생성 방식 | 예시 템플릿, 실제 모델 호출, 직접 작성 | 실제 동작만 표시 |
| 확인 질문·노트 | missing_fields·questions·review_notes를 이해 가능한 형태로 표시 | 추가 확인과 폼의 필수 입력은 별개 |
| 사진 | 유지할 파일과 처리 상태 확인 | 첨부 성공 여부와 내용 해석은 별개 |
| 접수 안내·행동 | 내부 접수 설명, 틈길에 알리기, 공식 경로 | 공식 민원 자동 접수로 오인하지 않음 |

작은 화면에서는 원문과 수정 영역을 세로로 배치해 두 내용을 모두 접근 가능하게 한다. 넓은 화면의 병렬 비교는 디자인 검토에서 정한다.

### AI 결과별 분기

출력 키와 고정 notice의 기준은 [앱 AI 안내](../prompts/README.md)·[스키마](../prompts/opinion-draft.schema.json)에 있다. 화면 편의를 위해 스키마나 고정 문구를 바꾸지 않는다.

| 결과 | 화면 동작 |
| --- | --- |
| draft | 부분 미확인 정보가 있어도 검토 가능한 초안으로 표시. 폼 조건을 별도 검사 |
| needs_input | 상황 등 확인이 필요한 이유를 보여 주고 입력 보완 또는 직접 작성으로 연결 |
| out_of_scope | 관련 상황을 다시 적을 수 있게 안내. 내용과 무관한 초안을 생성하지 않음 |
| 구조 오류·거부·시간초과 | 생성 실패 표시, 원문 유지, 직접 작성·재시도 제공 |
| 원문과 별도 입력 충돌 | 확인 질문과 양쪽 입력을 보여 주고 이용자가 수정. 앱이 임의로 한쪽을 선택하지 않음 |

AI가 location을 null로 출력했다고 이미 사용자가 선택·확인한 지점을 삭제하지 않는다. 원문 입력과 생성 결과의 차이를 보여 주고 어떤 위치를 제출할지 사용자가 확인한다. generated status는 내부 접수·처리 상태가 아니다.

### 수정과 재생성

- 이용자 수정값을 원문과 별도로 보존한다. 제목·상황은 제출 내용으로서 유효한지 검사한다.
- S05로 돌아가 원문을 바꾸면 기존 초안이 이전 입력에서 생성됐다는 것을 구분한다.
- 다시 정리를 요청할 때 이용자 수정 내용을 알림 없이 덮어쓰지 않는다. 새 결과를 비교·선택할 수 있게 하는 안을 사용한다.
- 발견 시점을 모르면 null 또는 미입력 상태를 유지한다. 제출 시각을 채워 넣지 않는다.
- AI의 missing_fields가 남아 있다는 이유만으로 제출 버튼을 일괄 차단하지 않는다.

### 제출

1. 사용자가 실제 전달할 위치·상황과 선택 첨부를 확인한다.
2. 폼·첨부 상태를 검사하고, 제출 요청 중 반복 실행을 막는다.
3. 저장 성공과 생성된 의견 ID를 확인하면 S07로 이동한다. 원문·검토 내용·생성 방식은 데이터 계약에 맞춰 연결한다.
4. 저장이 확정 실패하면 수정값과 원문을 유지한다. 결과 미확인은 C3에 따라 기존 요청 결과를 확인한다.
5. 초안 생성이나 화면 진입만으로 접수·상인 전달·상태 변경을 하지 않는다.

| --- | --- | --- |
| S06-T1 | 시점이 없는 draft 검토 | 날짜 생성 없음. 폼의 유효 조건만으로 제출 판단 |
| S06-T2 | AI 질문에 미확인 필드가 남음 | 질문 목록을 그대로 필수 입력으로 쓰지 않음 |
| S06-T3 | 수정 후 재생성 또는 원문 편집 | 이용자 수정과 생성 버전을 구별. 무단 덮어쓰기 없음 |
| S06-T4 | 제출 실패·결과 미확인 | 원문·수정값 유지. S07 성공으로 임의 이동하지 않음 |
| S06-T5 | 원문 위치와 선택 위치가 충돌 | 양쪽을 보여 주고 이용자 확인. 임의 주소 선택 없음 |

## S07 내부 접수 결과

| 항목 | 명세 |
| --- | --- |
| 목적 | 실제 저장된 내부 의견의 접수 결과와 다음 경로를 알린다 |
| 진입 | S06의 저장 성공, 해당 의견의 정당한 결과 재조회 |
| 필요한 맥락 | 저장된 의견 ID·접수 시각·접수 내용 요약 |
| 주요 행동 | 내 의견 보기 → S09, 시장으로 돌아가기 → S02, 별도 공식 경로 |
| 쓰기 | 없음. 진입·새로고침으로 같은 의견을 다시 제출하지 않음 |

### 표시

- 틈길 내부 접수라는 결과, 실제 접수 시각과 의견 식별 정보.
- 사용자가 검토한 제출 내용과 저장된 첨부 여부.
- 마이에서 처리 과정을 볼 수 있는 경로. 공식 민원 자동 접수나 대응 시간 보장은 표시하지 않는다.
- 가상 자료로 시연하는 경우 그 범위 안내.

의견 ID가 없거나 저장 결과를 확인하지 못했다면 성공 화면을 만들지 않는다. 읽기 실패·접근 불가·잘못된 ID는 C1·C2로 처리한다. 접수 완료 뒤 정정·삭제 기능은 D3·D5·D7의 정책 없이 추가하지 않는다.

### 인수 조건

| ID | 행동 | 기대 결과 |
| --- | --- | --- |
| S07-T1 | 저장 성공 후 진입 | 실제 저장 ID·시각 표시, 같은 의견의 S09 이동 |
| S07-T2 | 새로고침·뒤로가기·결과 재조회 | 중복 의견·초기 접수 이력 생성 없음 |
| S07-T3 | 잘못된 ID 또는 저장 결과 미확인 | 접수 완료로 표시하지 않음 |

이후의 시민·운영자·상인 화면은 [의견 처리 상세](OPINION_OPERATIONS.md), 공개·상태 정의는 [데이터 계약](../DATA_ACCESS.md)을 따른다.

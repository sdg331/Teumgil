# 화면 상세 명세 공통 기준

> 상세 설계안 · 2026-10-29. 실제 화면·API는 아직 없다. 기존 제품 기준과 이번에 제안하는 상호작용을 구분해 읽는다.

## 문서의 적용 순서

1. [제품 명세](../PRODUCT_SCREENS.md)의 R1–R8을 유지한다.
2. 데이터·상태·공개 범위는 [데이터 계약](../DATA_ACCESS.md)을 따른다.
3. 여기의 공통 동작과 해당 화면 상세를 함께 읽는다.
4. 기능에 영향을 주는 미결정 사항은 [PLANS](../PLANS.md)의 D 항목을 해결한 뒤 구현한다.

**기획 기준**은 기존 제품 의도, **상세 제안**은 이를 화면으로 옮기기 위한 동작안, **결정 필요**는 구현 결과가 달라져 선택해야 하는 항목이다. 상세 제안이 작성됐다는 이유로 기술·공개 정책까지 채택된 것은 아니다.

화면 ID는 설계·이슈·검증을 연결하는 이름이다. URL·API·컴포넌트 파일명은 앱 기술을 정한 뒤 대응시킨다. 문서의 데이터 이름도 개념 필드이며 확정된 DB 컬럼이 아니다.

화면·세부 동작·인수 조건의 ID는 [ID 대장](../spec-ids.json)에서 관리한다. 추가·이동·폐기는 [ID 관리 규칙](../ID_POLICY.md)을 따른다. 기존 ID를 단순 정렬이나 이름 변경 때문에 바꾸지 않는다.

## C1. 접근과 진입

| 구분 | 공통 동작 제안 |
| --- | --- |
| 시민 탐색 | 로그인 없이 시장·점포를 둘러보는 구상을 따른다. 실제 공개 범위·인증은 D7 결정 |
| 개인 자료 | 장보기·내 의견을 열 때 선택된 본인/데모 주체를 식별한다. 다른 사람 자료를 기본값으로 사용하지 않음 |
| 운영자·상인 | 진입과 읽기·쓰기마다 역할 및 대상 의견·전달의 관계를 확인. URL·역할 선택만으로 접근 허용하지 않음 |
| 접근 불가 | 본문과 첨부를 숨기고 접근할 수 없음을 안내. ID를 바꿔 다른 자료를 탐색하게 하지 않음 |
| 잘못된 대상 | 삭제·존재하지 않는 자료는 대상 없음 화면과 돌아갈 경로 제공. 보안상 존재를 숨기는 응답 정책은 D7에서 결정 |
| 가상 역할 | 데모 역할과 실제 계정 인증을 구별. 변경 전 미저장 입력은 C4에 따라 처리 |

실제 권한 검증은 서버의 책임이다. 가상 자료만 쓰는 시안에서는 역할별 표시를 검토할 수 있지만 보안 검증 완료로 설명하지 않는다.

## C2. 읽기 상태

| 상태 | 보여 줄 것 | 다음 행동 |
| --- | --- | --- |
| 최초 읽기 중 | 무엇을 불러오는지, 조작 가능한 탐색 경로 | 로딩 중 빈 목록으로 오인하지 않게 함 |
| 정상·자료 있음 | 마지막으로 성공한 요청의 대상과 내용 | 선택·다음 화면 |
| 정상·자료 없음 | 검색 결과 없음/저장된 항목 없음 등 이유를 구분 | 검색 수정·재료 입력 등 해당 행동 |
| 읽기 실패 | 불러오지 못한 범위와 재시도 | 기존 입력·검색 조건 보존 |
| 일부만 실패 | 성공한 정보와 실패한 구역을 구분 | 실패 구역만 재시도 가능하게 제안 |
| 접근 불가·대상 없음 | 본문 없는 안내와 돌아가기 | C1 적용 |

이전 결과를 남긴 채 새 결과를 기다릴 때는 현재 적용된 검색 조건을 표시한다. 이전 요청이 늦게 끝나 최신 조건의 결과를 덮어쓰지 않도록 한다.

## C3. 쓰기와 결과 확인

상태는 **입력 중 → 검증 → 저장 요청 중 → 성공 / 확정 실패 / 결과 미확인**으로 구분한다.

- 요청 중 같은 동작의 버튼을 중복 실행하지 않게 한다. 다른 데이터를 변경하는 조작도 충돌 여부에 맞춰 제한한다.
- 성공은 실제 저장 결과를 확인한 후 표시하고 다음 화면에 같은 대상 ID를 전달한다.
- 입력 검증 실패는 해당 항목의 오류와 수정 방법을 표시한다. 나머지 입력을 지우지 않는다.
- 확정 실패는 입력을 유지하고 재시도 또는 취소 경로를 제공한다. UI를 먼저 바꿨다면 저장 실패를 반영해 복구한다.
- 시간초과·연결 끊김으로 저장 여부를 모르면 실패 또는 성공으로 단정하지 않는다. 기존 제출을 확인하거나 중복 방지 수단으로 재시도하는 정책을 D1에서 정한다.
- 의견·상인 답변·상태 변경을 재시도하면서 중복 기록이 생기지 않는지 확인한다. 프런트 버튼 잠금만으로 해결됐다고 보지 않는다.

## C4. 이동과 입력 보존

- 같은 편집 흐름에서 이전 화면으로 돌아갈 때 작성값과 선택 위치를 유지하는 안을 사용한다.
- 수정 중 탭 이동·뒤로가기·역할 전환으로 입력이 사라질 수 있으면 유지 범위를 설명하고, 폐기 시 확인할 수 있게 한다.
- 새로고침·창 종료·다른 기기에서의 복구는 D1의 저장 정책에 따른다. 자동 저장·복구가 없는데 된다고 안내하지 않는다.
- 취소와 저장을 구분한다. 취소로 서버 데이터나 다른 사람의 기록이 삭제되지 않게 한다.
- 목록→상세→목록 복귀 시 검색어·선택 시장·필터를 유지하는 안을 사용한다. 스크롤 복구는 실제 화면에서 확인한다.

## C5. 입력과 검증

| 항목 | 공통 규칙 |
| --- | --- |
| 이름표 | 입력란 밖에 표시. placeholder로 대체하지 않음 |
| 공백 | 필수 입력은 공백만 있는 값을 거부. 검색 비교용 정규화와 이용자 원문 보존을 구분 |
| 검증 시점 | 제출·저장 시 전체 검사. 이미 오류를 확인한 항목은 수정 후 다시 검사 |
| 오류 위치 | 해당 항목과 연결된 설명. 여러 오류가 있으면 첫 오류로 초점 이동하는 안 |
| 길이·파일 제한 | 서버·저장·제공자와 같은 규격을 사용. 숫자는 D1·D5에서 확정 후 반영 |
| 선택 입력 | 이름표·안내에 선택 여부 표시. 비어 있다고 임의 값을 채우지 않음 |

업로드 종류·개수·크기·보관 정책이 정해지기 전에는 완료된 업로드 기능처럼 표시하지 않는다. 초안 AI의 추가 질문 목록은 필수 입력 규칙을 대체하지 않는다.

## C6. 모바일·접근성

[디자인 초안](../DESIGN_DRAFT.md)의 크기·간격 제안을 따른다. 좁은 화면에서는 아래 순서를 실제로 확인한다.

1. 제목 → 현재 대상·상태 → 주요 내용 → 관련 행동이 읽히는가?
2. 320px 너비·글자 200% 확대에서 입력과 주요 버튼이 잘리지 않는가?
3. 키보드로 탐색·선택·닫기가 가능하고 초점이 보이는가?
4. 제출·오류·목록 변경을 색이나 짧은 토스트 하나에만 의존하지 않는가?
5. 고정 하단 탭·버튼이 본문, 키보드, 안전 영역을 가리지 않는가?
6. 지도에 표시된 점포·위치를 목록이나 설명으로도 찾을 수 있는가?

## C7. 상태·출처·문구

문구는 [UX_COPY](../UX_COPY.md), 처리 상태명은 [데이터 계약](../DATA_ACCESS.md)을 참조한다. 화면 명세에 예시를 넣더라도 해당 기준의 의미를 바꾸지 않는다.

- 가상 자료는 가상임을 표시한다. 템플릿과 실제 AI 호출, 사용자가 직접 쓴 정보와 확인된 정보를 구별한다.
- 출처·확인일이 없으면 없는 상태를 표시한다. 날짜·가격·재고·답변·처리 성과를 채워 넣지 않는다.
- 공식 경로는 내부 처리와 독립적으로 제공한다. 정확한 대상 URL·앱 연결 방식은 구현 시 공식 안내를 확인한다. 이 명세에서 경로를 검증했다고 주장하지 않는다.
- 긴급 위험 안내는 초안 생성·접수 성공·운영자 확인과 무관하게 확인할 수 있어야 한다.

## C8. 인수 검증 기록

각 상세 화면의 Sxx-Tn은 앞으로 동작을 검증할 조건이다. 현재 통과한 테스트가 아니다. 구현 시 화면 ID, 시작 데이터·역할, 행동, 관찰 결과, 실행 환경과 미결정 사항을 연결해 기록한다. 스크린샷만으로 저장·권한·이력의 성공을 판정하지 않는다.
